    • Agent Cloud with RSC

      Agent Cloud with RSC provides a comprehensive solution for discovering AI agents in your environment, understanding which tools they have access to, detecting risky actions they perform on your data and configurations, and rewinding unauthorized changes without downtime.

      • Introduction to Agent Cloud
      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Choose your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Choose where it runs before you connect your AI providers and agents.

      • Connect your AI agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

        • How policies work

          A policy is a named rule with a severity that Agent Cloud evaluates against your agents, tools, and sessions. When agent activity breaks a policy, Agent Cloud records a violation or an alert and, depending on the policy's enforcement mode, can stop the action.

        • Plan your policy rollout

          Introduce policies in Monitor mode, review the alerts they produce, and move a policy to Block only after it behaves as you expect and only on connections that support blocking.

        • Enforcement modes

          A policy's enforcement mode determines what happens when agent activity breaks it: Monitor records an alert, and Block stops the action before it runs.

        • How blocking works

          A Block policy lets Agent Cloud stop an agent action before it takes effect, inline with the agent's own execution, instead of only flagging it afterward.

        • Agent Cloud system policies

          Agent Cloud includes multiple system policies. These policies are not enabled by default. You can enable them from the Policies page.

        • Agent Cloud policy packs

          Agent Cloud policy packs are curated collections of system policies you can add to your Agent Cloud account to enable a focused set of controls for a specific risk area, compliance framework, or industry.

        • Custom policies

          A custom policy is a rule that you write in plain English. The Semantic AI Governance Engine (SAGE) turns it into a policy that it judges against agent activity by intent, not by matching keywords.

          • SAGE architecture and policy evaluation

            The Semantic AI Governance Engine evaluates AI agent actions against custom policies in Agent Cloud and uses a small language model to enforce those policies based on semantic intent rather than keyword matching.

          • Creating custom policies using an AI judge

            Create a custom policy using an AI judge in Agent Cloud to control which tools, models, and actions AI agents in your environment can use.

          • Testing a custom policy using manual input

            Submit sample content to test that a custom policy correctly identifies violations before you rely on it in production.

          • Testing a custom policy using a backtest

            Run a backtest against recent session history to test that a custom policy correctly identifies violations before you rely on it in production.

          • Editing a custom policy using an AI judge

            Modify the configuration, conditions, or enforcement settings of an existing Agent Cloud custom policy to align with updated organizational security requirements.

        • Viewing the Agent Cloud policies

          View the list of policies that govern Agent Cloud.

        • Enabling or disabling Agent Cloud policies

          Enable or disable policies to control which agent actions Agent Cloud monitors and enforces.

        • Alerts and violations

          Alerts and violations are the findings that your policies produce. An alert is a specific action or message that broke a policy. A violation is a standing configuration that breaks one.

        • Viewing insights

          View the Insights page to review security recommendations and posture improvements identified by Agent Cloud.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

      • Administer Agent Cloud

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

Editing a custom policy using an AI judge

Modify the configuration, conditions, or enforcement settings of an existing Agent Cloud custom policy to align with updated organizational security requirements.

Before you begin

Editing a custom policy requires:
  • An active Rubrik Security Cloud (RSC) account with Agent Cloud administrative privileges.
  • Familiarity with the natural language or rule-based conditions used to define the policy.

About this task

Editing a custom policy enables you to refine how Agent Cloud monitors or blocks agent actions. Updates to a policy take effect immediately for all subsequent agent activity within the defined scope.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Click Policies.
    Agent Cloud displays the Policies page, which contains a list of the policies configured in Agent Cloud.
  4. Click next to the policy you want to edit, then click Edit.
    Agent Cloud displays the Review and Edit Policy wizard.
  5. If necessary, revise characteristics to strengthen the policy.
  6. Click Reanalyze.
    The Review and Edit Policy wizard evaluates the policy with the edited characteristics and provides an updated rating.

    If there are new recommendations, repeat the process until the Review and Edit Policy wizard indicates that you have a strong policy.

  7. Click Next.
    The Review and Edit Policy wizard moves to the Policy Scope page.
  8. Optional: Determine the scope of the AI agents or tools this policy affects.
    You can use the Agents or Tools tabs on the Policy Scope page to determine which agents or tools to include or exclude from the policy.
    ScopeDescription
    All agents, or All tools The default. When selected, the policy applies to every agent or tool.

    Clicking Select Agents or Select Tools and then Edit enables you to specify which agents or tools are excluded from the policy.
    Specific agents only, or Specific tools only Clicking Specific agents only or Specific tools only and then Edit enables you to specify which agents or tools are included in the policy.
  9. Click Next.
    The Review and Edit Policy wizard moves to the Finalize Policy Details page.
  10. Review the policy details and update as necessary.
    FieldDescription
    Name Name of the policy
    Description Optional description for the policy
    Severity The severity that Agent Cloud assigns to violations of the policy
    Status Whether the policy is enabled or disabled
    Categories Categories to which you can assign the custom policy. These are independent from the system-provided pack categories. The available categories are:
    • Security: Defends against adversarial attacks and dangerous agent behaviors
    • Operational: Guardrails that control what the agent is allowed to do at runtime
    • Content Safety: Detects harmful, abusive, or inappropriate language in agent responses
    • Compliance: Protects sensitive data and enforces regulatory and organizational obligations
    • Configuration: Assesses the quality and correctness of how the agent is set up before it runs
    Source Indicates that the policy judge is an LLM
    Type Read-only. Set when the policy was created.
    Enforcement Determines the enforcement level of the policy, Monitor, Block, or Ask. Custom policies always have an enforcement of Monitor.
  11. Click Save.

Results

Agent Cloud updates the policy and displays the new status in the Policies table. Any future agent activity that meets the updated conditions triggers a violation or alert based on the selected enforcement type.
