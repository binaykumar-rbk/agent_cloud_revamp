        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. MCP gateway (Early access)

An MCP gateway is a single governed endpoint between your AI agents and the MCP servers that they use. It authenticates the person behind each agent against your identity provider and forwards only the tool calls that your MCP access policies allow.

Note:
The MCP gateway is an early access feature. For how to opt in, see Early access features.

Without a gateway, each agent connects to each MCP server directly, each server handles its own authentication, and there is no central record of which person can call which tool. With a gateway, you point your agents at one endpoint instead of many. For every tool call, the gateway:

  1. Authenticates the user against your identity provider, Microsoft Entra ID or Okta.
  2. Checks the call against the access policy for that MCP server or tool.
  3. Forwards the call to the MCP server only if the policy allows it.

An MCP server with no access rules denies every call. Access is granted explicitly, never assumed. For more information, see MCP access policies (Early access).

Key concepts

  • One gateway per identity provider tenant. You connect the identity provider first, and you cannot change it after the gateway is created.
  • A stable endpoint. The gateway's endpoint URL is what you configure in each agent, and it stays the same when you change the servers or access rules behind it.
  • Changes deploy in the background. When you add a server or change access rules, the change is pending until the gateway is redeployed with it, which happens automatically. Each change shows whether it has reached the gateway.
  • Added and discovered MCP servers. The MCP servers inventory shows both the servers that you add to a gateway and the servers that Agent Cloud discovers on endpoints. Only servers added to a gateway are governed by it. For more information, see Viewing MCP server details.

Limitations

  • Access policies are enforced at the gateway, not at the MCP server. A caller who can reach an MCP server directly bypasses the gateway, so restrict direct access to servers that the gateway fronts.
  • Only MCP servers that use the Streamable HTTP transport are supported. Servers that use the older SSE transport are not forwarded by the gateway.
  • If one access rule on any server cannot be applied, the deploy fails and no pending change on that gateway takes effect until the rule is fixed.
