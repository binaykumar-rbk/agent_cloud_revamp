  • Agent Cloud

    Detect risky actions caused on your data by autonomous AI agents, and rewind the actions to repair changes to the data and configurations without downtime.

    • Agent Cloud with RSC

      Agent Cloud with RSC provides a comprehensive solution for discovering AI agents in your environment, understanding which tools they have access to, detecting risky actions they perform on your data and configurations, and rewinding unauthorized changes without downtime.

      • Introduction to Agent Cloud

        Describes what Agent Cloud does, how it works, the key concepts and terms, and the features that are available in early access.

      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Deploy your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Decide where it runs before you connect your AI providers and agents.

      • Connect your agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

        • Agent Cloud support matrix

          Agent Cloud supports multiple platform integrations, each with varying capabilities for AI agent discovery, session activity monitoring, policy enforcement, configuration violations, monitoring alerts, blocking, and ask enforcement.

        • Builder platforms

          Describes how to connect platforms where you build and host your own agents, such as Microsoft Copilot Studio, Google Cloud Gemini Enterprise, and Amazon Bedrock.

          • Microsoft Copilot Studio deployed in Agent Cloud

            Agent Cloud reads Microsoft Copilot Studio agents and conversation transcripts through the Dataverse API and, when you enable tool blocking, intercepts tool calls in real time through the external threat detection integration of Copilot Studio.

          • Microsoft Foundry (new) deployed in Agent Cloud

            Agent Cloud reads Microsoft Foundry (new) agent activity from the Azure Application Insights resource linked to a Foundry project, through a service principal that you grant read access.

            • Microsoft Foundry (new) requirements for Agent Cloud

              Microsoft Foundry (new) integration requires specific Azure administrative roles, resource identifiers, and service principal permissions to enable agent discovery and log ingestion.

            • Deploying Microsoft Foundry (new) on Agent Cloud

              Deploy Microsoft Foundry (new) to Agent Cloud by establishing a secure service principal connection to your Azure tenant and mapping project resources.

          • Microsoft Foundry (classic) deployed in Agent Cloud

            Agent Cloud reads Microsoft Foundry (classic) agent activity from the Azure Application Insights resource linked to a Foundry project, through a service principal that you grant read access. Only instrumented agents are observed.

          • Google Cloud Gemini Enterprise in Agent Cloud

            Agent Cloud uses a Google Cloud service account that you create to discover agents and read their conversation sessions in a Google Cloud project, covering both Gemini Enterprise and Gemini Enterprise Agent Platform (Vertex AI Agent Engine).

          • AWS Bedrock Agents deployed in Agent Cloud

            Agent Cloud reads Amazon Bedrock model invocation logs from Amazon CloudWatch Logs or an Amazon S3 bucket, through an IAM role in your AWS account that Agent Cloud assumes.

          • Amazon Bedrock AgentCore deployed in Agent Cloud

            Agent Cloud reads the OpenTelemetry runtime logs that Amazon Bedrock AgentCore writes to Amazon CloudWatch, through an IAM role in your AWS account that Agent Cloud assumes.

        • Enterprise apps

          Describes how to connect vendor-managed AI applications that your employees use: ChatGPT Enterprise, Claude Enterprise, and Microsoft 365 Copilot.

        • AI gateways

          Custom agents that you build connect to Agent Cloud through the Rubrik AI gateway or through your existing LiteLLM proxy. Agents that export OpenTelemetry traces connect under Observability.

        • Observability

          Describes how to send OpenTelemetry traces from your agent frameworks to Agent Cloud.

        • Endpoint detection

          The Rubrik endpoint detection binary runs on employee devices to discover the AI agents installed there and the identities that use them, and, for supported agents, to capture their sessions and enforce policies in real time.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Govern and control

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind agent actions

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. You can start a rewind from the Sessions page, or from any page that displays the action or alert detail tray. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

      • Administer Agent Cloud

        Control who can view and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

Microsoft Foundry (new) requirements for Agent Cloud

Microsoft Foundry (new) integration requires specific Azure administrative roles, resource identifiers, and service principal permissions to enable agent discovery and log ingestion.

Prerequisites

Note:
Agent Cloud supports Microsoft Foundry (new), which is referred to throughout this topic as Microsoft Foundry.
  • An existing Microsoft Foundry project at ai.azure.com.
  • An Application Insights resource associated with the Foundry project and in the same region as the Foundry project. If one does not yet exist, you can create one during deployment.
  • Azure administrator access with rights to grant administrator consent and to assign roles (for example, Owner or User Access Administrator) on the Application Insights resource.
  • An active RSC account with Data Source Management privileges.

Required Azure roles and permissions

The following table describes the permissions required to establish a secure connection between Microsoft Foundry and Agent Cloud.
Component Requirement
Service Principal Granting administrator consent during setup automatically registers an enterprise application named Rubrik Agent Cloud (Foundry) in your Azure tenant. You assign the Log Analytics Reader role to this identity, as described in Deploying Microsoft Foundry (new) on Agent Cloud.
Log Analytics You must assign the Log Analytics Reader role to the Rubrik Agent Cloud (Foundry) service principal on the Application Insights resource so that Agent Cloud can retrieve agent logs.
Admin Consent The account you use to sign in must have permission to grant administrator consent in the Azure tenant.
