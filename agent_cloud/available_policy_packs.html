    • Agent Cloud with RSC

      Agent Cloud with RSC provides a comprehensive solution for discovering AI agents in your environment, understanding which tools they have access to, detecting risky actions they perform on your data and configurations, and rewinding unauthorized changes without downtime.

      • Introduction to Agent Cloud
      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Choose your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Choose where it runs before you connect your AI providers and agents.

      • Connect your AI agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

        • How policies work

          A policy is a named rule with a severity that Agent Cloud evaluates against your agents, tools, and sessions. When agent activity breaks a policy, Agent Cloud records a violation or an alert and, depending on the policy's enforcement mode, can stop the action.

        • Plan your policy rollout

          Introduce policies in Monitor mode, review the alerts they produce, and move a policy to Block only after it behaves as you expect and only on connections that support blocking.

        • Enforcement modes

          A policy's enforcement mode determines what happens when agent activity breaks it: Monitor records an alert, and Block stops the action before it runs.

        • How blocking works

          A Block policy lets Agent Cloud stop an agent action before it takes effect, inline with the agent's own execution, instead of only flagging it afterward.

        • Agent Cloud system policies

          Agent Cloud includes multiple system policies. These policies are not enabled by default. You can enable them from the Policies page.

        • Agent Cloud policy packs

          Agent Cloud policy packs are curated collections of system policies you can add to your Agent Cloud account to enable a focused set of controls for a specific risk area, compliance framework, or industry.

          • Available policy packs

            Information on the policy packs available on Agent Cloud.

          • Viewing the policy packs

            View the list of the policy packs available in Agent Cloud.

          • Viewing the policies in a policy pack

            View the policies a policy pack contains, including the name, category, and current status of each policy in the account.

          • Adding policy packs to an account

            Add a policy pack to an RSC account to include its system policies in the list of policies that appear on the My Policies page.

          • Removing policy packs from an account

            Remove a policy pack from a RSC account. Once removed, the policies the pack provides stop generating new alerts.

        • Custom policies

          A custom policy is a rule that you write in plain English. The Semantic AI Governance Engine (SAGE) turns it into a policy that it judges against agent activity by intent, not by matching keywords.

        • Viewing the Agent Cloud policies

          View the list of policies that govern Agent Cloud.

        • Enabling or disabling Agent Cloud policies

          Enable or disable policies to control which agent actions Agent Cloud monitors and enforces.

        • Alerts and violations

          Alerts and violations are the findings that your policies produce. An alert is a specific action or message that broke a policy. A violation is a standing configuration that breaks one.

        • Viewing insights

          View the Insights page to review security recommendations and posture improvements identified by Agent Cloud.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

      • Administer Agent Cloud

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

Available policy packs

Information on the policy packs available on Agent Cloud.

The following table describes the policy packs that are available on Agent Cloud.
Policy pack Category Description
Agent Permissions & Boundaries Security Constrains what Agent Cloud enables an AI agent to do at runtime. It limits the AI agent to the smallest set of tools it needs to do its job, the models the agent may invoke, the environments in which the agent may perform write or destructive actions, and the commitments the agent may make on behalf of the organization.

Use this policy pack to prevent an authorized agent from operating outside its intended scope, regardless of whether the deviation is caused by a misconfigured prompt, a compromised tool description, an over-permissive model selection, or an unintended escalation in production.
AI Agent Essentials Essentials The baseline control set that Agent Cloud applies to every RSC account. It contains the universal policies that defend against the risks shared by every AI agent deployment, independent of industry, workload, or regulatory environment. Agent Cloud adds this pack to new accounts automatically so that core protections are in place from day one, and the pack remains the foundation to which all other packs build on.

Use this pack as the always-on safety net for the account. It is intentionally broad and conservative: it covers the failure modes that are most likely to cause customer-visible incidents, data exposure, or loss of trust in AI agent output, while leaving industry-specific and use-case-specific controls to the opt-in packs.
Audit & Accountability Compliance and governance Ensures that every action an AI agent takes can be traced back to a responsible party and that security-relevant events are captured in a form suitable for compliance review. This policy pack closes the gaps that ordinary logging tools leave behind when they are applied to AI agents. Because an AI agent decides for itself which model calls and tool calls to make, a single user request can lead to many downstream actions, and ordinary logs do not connect those actions back to the user or the request that caused them.

Use this pack to satisfy internal audit programs, external regulatory obligations, and incident response requirements that depend on a complete, attributable record of agent activity.
Code Execution Safety Security Inspects code that an AI agent produces, suggests, or hands off to a runtime, and detects patterns that are unsafe to execute. AI agents increasingly generate code as part of normal operation — composing SQL queries, emitting shell commands, returning snippets for a developer to run, or invoking a code-execution tool directly. This pack is the control layer that sits between the agent's output and the place where that code is actually executed.

Use this pack to prevent an agent from introducing injection vulnerabilities, executing obfuscated payloads, or driving a code-execution tool with input that has not been validated.
Coding Agent Security Security Governs AI agents whose primary function is to write, modify, or ship software — coding assistants, IDE-integrated agents, pair-programmers, and other such agents.

Coding agents run with elevated access to the tools that build the organization's software, and a single misstep can cascade far beyond the agent itself, through committed secrets, unreviewed dependency additions, and general misuse.

This pack enforces the controls specific to this class of agent, separating what a coding agent may propose from what it may actually commit, install, or deploy.

Use this pack on any AI agent that:
  • Clones, reads, edits, commits, or pushes to source repositories
  • Installs or updates dependencies
  • Authors or modifies CI/CD configuration
  • Has access to developer credentials or signing keys
  • Can trigger builds or deployments on behalf of an engineering team.
Content Safety Content safety Governs the tone, language, and self-representation of an AI agent's output. It blocks responses that would be harmful, offensive, or deceptive to the end user, and it prevents the agent from misrepresenting itself as a human. The pack is concerned with what the agent says to people, not with what the agent does in downstream systems.

Use this pack on any agent that produces output that reaches an end user — customers, employees, partners, or members of the public — through chat, email, voice, ticketing systems, or any other conversational surface.
Data Exposure Prevention Security Blocks the leakage of sensitive data across every surface that an AI agent touches. It inspects what the agent receives as input, what it passes into tool calls, and what it returns as output, and stops sensitive content from crossing trust boundaries it should not cross — whether outbound to an end user, sideways into a third-party tool, or upstream into a model provider.

Use this pack on any agent that is exposed to regulated data, customer data, internal business intelligence, or operational secrets, and that interacts with external models, external tools, or external users.
Data Governance Compliance and governance

Enforces the handling rules that the organization has committed to for regulated and sensitive data, applied to every AI agent interaction. Where Data Exposure Prevention focuses on stopping leaks, Data Governance focuses on whether the data was permitted to be in that interaction at all, how it was handled, where it was sent, and whether the activity is consistent with the policies the organization is accountable for upholding.

Use this pack to align AI agent activity with the data classification, residency, retention, and lawful-use rules that already govern the rest of the organization, and to produce the evidence that internal and external auditors expect.
Financial Services AI Governance Industry Tailors Agent Cloud's controls to the regulatory and operational requirements of banking, capital markets, insurance, and other financial services workloads. It addresses the specific failure modes that carry outsized risk in financial services — commitments made on behalf of the firm, disclosure of competitively sensitive information, and statements that could be construed as financial advice or a binding offer — and adds the recordkeeping and supervision controls that financial regulators expect.

Use this pack on any AI agent that interacts with customers, counterparties, or internal teams in a financial services context, or that has access to pricing, strategy, account, or transaction data.
Healthcare AI Governance Industry Tailors Agent Cloud's controls to the safety, privacy, and equity requirements of healthcare workloads. It enforces the practices that healthcare regulators, accreditation bodies, and patient-safety programs expect of any AI system that touches clinical workflows, patient communications, or protected health information. The pack is derived from the Coalition for Health AI (CHAI) Responsible AI Guide and codifies its principles as runtime controls on agent behavior.

Use this policy pack on any AI agent that interacts with patients or clinicians, that handles clinical or administrative health data, or that participates in care delivery, scheduling, billing, or member-services workflows in a healthcare context.
Prompt Security Security Protects an AI agent from being given instructions it should not follow, whether those instructions come from the user prompt or from content the AI agent reads while doing its work. Modern agents take instructions from many sources beyond the user prompt — system prompts, retrieved documents, tool outputs, web content, email bodies, ticket fields, and the descriptions of the tools themselves — and any of those surfaces can be used to subvert the AI agent's intended behavior. Prompt Security inspects all of them and detects attempts to override, exfiltrate, or poison the instructions the agent is acting on.

Use this pack on every agent that accepts free-form user input or that consumes content from external sources, including any agent that performs retrieval, browses the web, reads documents, or calls tools that return untrusted text.
Responsible AI Compliance and governance Aligns AI agent behavior with the cross-cutting principles that responsible AI programs commit to — transparency, accountability, human oversight, and the avoidance of foreseeable harm. Where industry packs codify the rules of a specific regulator and security packs defend against specific attack patterns, Responsible AI enforces the conduct standards that the organization has made to its customers, employees, regulators, and the public about how its AI systems behave.

Use this pack to operationalize the organization's responsible AI principles as runtime controls, rather than leaving them as aspirational statements that are difficult to evidence in production.
Tool & Plugin Integrity Security Validates the tool catalog that an AI agent operates against. AI agents make routing decisions based on the names, descriptions, parameter schemas, and metadata of the tools available to them, and that surface is a security boundary in its own right. A description that is ambiguous, deceptive, contradictory, or carries a hidden instruction can cause the agent to invoke the wrong tool, leak data into the wrong destination, or follow injected guidance — even when every individual tool is itself well-behaved.

Use this pack on any agent that exposes more than a handful of tools, that consumes plugins or connectors from a third-party marketplace, or that allows tool registration to be performed by teams outside a central review function.
