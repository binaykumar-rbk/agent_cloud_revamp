      Agent Cloud with RSC provides a comprehensive solution for discovering AI agents in your environment, understanding which tools they have access to, detecting risky actions they perform on your data and configurations, and rewinding unauthorized changes without downtime.

      • Introduction to Agent Cloud

        Describes what Agent Cloud does, how it works, the key concepts and terms, and the features that are available in early access.

      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Deploy your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Decide where it runs before you connect your AI providers and agents.

      • Connect your agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Govern and control

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

        • How policies work

          A policy is a named rule with a severity that Agent Cloud evaluates against your agents, tools, and sessions. When agent activity breaks a policy, Agent Cloud records a violation or an alert and, depending on the policy's enforcement mode, can stop the action.

        • Enforcement modes

          A policy's enforcement mode determines what happens when agent activity breaks it: Monitor records an alert, Block stops the action before it runs, and Ask hands the action to the agent's own approval prompt.

        • How blocking works

          A Block policy lets Agent Cloud stop an agent action before it takes effect, inline with the execution of the agent, instead of only flagging it afterward.

        • Agent Cloud system policies

          Agent Cloud includes multiple system policies. These policies are not enabled by default. You can enable them from the Policies page.

        • Agent Cloud policy packs

          Agent Cloud policy packs are curated collections of system policies you can add to your Agent Cloud account to enable a focused set of controls for a specific risk area, compliance framework, or industry.

        • Custom policies

          A custom policy is a rule that you write in plain English. The Semantic AI Governance Engine turns it into a policy that it judges against agent activity by intent, not by matching keywords.

        • Alerts and violations

          Alerts and violations are the findings that your policies produce. An alert is a specific action or message that broke a policy. A violation is a standing configuration that breaks one.

        • Viewing insights

          View the Insights page to review security recommendations and posture improvements identified by Agent Cloud.

        • MCP access policies (Early access)

      • Rewind agent actions

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. You can start a rewind from the Sessions page, or from any page that displays the action or alert detail tray. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

        Control who can view and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

MCP access policies (Early access)

An MCP access policy decides which identities can use an MCP server, or a specific tool on it, through your MCP gateway.

Note:
MCP access policies are an early access feature, available with the MCP gateway. For how to opt in, see Early access features.

MCP access policies are enforced at the MCP gateway. When an agent calls a tool through the gateway, the gateway identifies the user through your identity provider and checks the call against the access policy for that server or tool. Only allowed calls are forwarded to the MCP server.

Define access

You set access when you add an MCP server to the gateway, and you can change it later. Access can apply to a whole server or to individual tools:

  • All users: Everyone in your organization.
  • Specific users and groups: Only the users and groups from your identity provider that you select, optionally excluding some of them.
  • No one: No access, until you grant it.
  • Custom access: A rule written in Rego, the Open Policy Agent policy language, for conditions that the other options cannot express. The rule must start with package orchestrator.

A server with no access rules denies every call. Access is granted explicitly, never assumed.

How changes take effect

A change to an access policy takes effect when the gateway is redeployed with it, which happens automatically. Until then, the change shows as pending. If a rule cannot be applied, the deploy fails rather than dropping the rule, because dropping a deny would widen access. No pending change on that gateway takes effect until the rule is fixed.

Limitations

Access policies govern calls that go through the gateway. A caller who can reach an MCP server directly bypasses them.

Related concepts
  • MCP gateway (Early access)
    An MCP gateway is a single governed endpoint between your AI agents and the MCP servers that they use. It authenticates the person behind each agent against your identity provider and forwards only the tool calls that your MCP access policies allow.
  • How policies work
    A policy is a named rule with a severity that Agent Cloud evaluates against your agents, tools, and sessions. When agent activity breaks a policy, Agent Cloud records a violation or an alert and, depending on the policy's enforcement mode, can stop the action.
