OpenTelemetry

An OpenTelemetry connection monitors AI agent activity from your existing agent frameworks and displays it as sessions in Agent Cloud.

An OpenTelemetry connection captures user prompts, agent responses, and tool calls as sessions in Agent Cloud. After you create the OpenTelemetry connection, Agent Cloud provides an OTLP/HTTP endpoint URL and a bearer token. Configuring your agent framework to export traces to that endpoint allows Agent Cloud to ingest the data for monitoring, policy evaluation, and alerting.

Agent Cloud ingests OpenTelemetry traces that follow the GenAI semantic conventions described in OpenTelemetry GenAI semantic conventions. Agent Cloud supports any framework or library that emits gen_ai.* attributes. Each session in Agent Cloud corresponds to one value of the gen_ai.conversation.id attribute. If your AI agent does not set this attribute, its activity does not appear as a session.

Capabilities

This table lists what the OpenTelemetry connection supports.
Capability Support
Discovery Agents, tools, sessions, identities
Session activity User prompts, agent responses, tool calls
Violations Yes
Monitor Yes
Block No. Traces are exported after the fact, so block policies behave like monitor policies.

How sessions are formed

Sessions appear in Agent Cloud approximately 1–2 minutes after your AI agent runs. For a session to be created with visible content, your spans must satisfy two conditions:

  • gen_ai.conversation.id must be present; spans without this attribute are not grouped into a session.
  • Content capture must be enabled in your instrumentation; otherwise, the session ingests without prompts or responses. Each framework controls content capture differently. For the framework instrumentation topics, see Supported OpenTelemetry frameworks.

OpenTelemetry requirements

Information about the permissions, endpoint configuration, and span attributes required to connect Agent Cloud to an agent instrumented with OpenTelemetry.

This table describes the requirements for connecting Agent Cloud to an agen instrumented with OpenTelemetry.
Component Description
Administrator permissions You must have administrator access to the Agent Cloud environment to create a connection.
Bearer token Agent Cloud displays the bearer token once when it creates the connection.

Rubrik recommends that you copy and store the bearer token as the RUBRIK_OTLP_TOKEN environment variable in your agent environment before closing the wizard.
Content capture You must enable content capture for prompts and responses to appear in sessions.

The setting name varies by framework; you can see the Supported OpenTelemetry frameworks topics for the correct setting.
gen_ai.conversation.id span attribute Required on every span. Spans without this attribute are not grouped into a session in Agent Cloud.

In most frameworks, you must set this attribute as a Resource attribute or verify that your framework sets it automatically.
GenAI semantic conventions Your agent framework must be OpenTelemetry compatible and produce AI activity data in the standard format described in OpenTelemetry GenAI semantic conventions. Agent Cloud supports any tool or library that emits gen_ai.* conventions.
OpenTelemetry connection Connecting Agent Cloud to an agent instrumented with OpenTelemetry requires an OpenTelemetry connection created in Agent Cloud.

Copy the OTLP endpoint URL and bearer token from the connection wizard. For more information, see Creating an OpenTelemetry connection.
OTLP/HTTP endpoint URL Agent Cloud generates the endpoint URL when you create the connection.
The connection endpoint URL ends in /v1/otlp.
  • If you set the general exporter endpoint, for example, OTEL_EXPORTER_OTLP_ENDPOINT, you must use this base URL. That is, the root endpoint you assign to OTEL_EXPORTER_OTLP_ENDPOINT. The exporter appends /v1/traces automatically.
  • If you set the trace-specific exporter endpoint, for example, OTEL_EXPORTER_OTLP_TRACES_ENDPOINT, you must use the full path: .../v1/otlp/v1/traces. Nothing is appended automatically.
Python and pip You must have Python and pip available in your agent environment.
RUBRIK_OTLP_TOKEN environment variable You must set the RUBRIK_OTLP_TOKEN environment variable to the bearer token value.

Creating an OpenTelemetry connection

Create an OpenTelemetry connection to obtain the OTLP endpoint URL and bearer token that your instrumented AI agents use to export traces to Agent Cloud.

Before you begin

You must have administrator access to the Agent Cloud environment.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Select Connectors.
  4. Click Add Connection > OpenTelemetry.
    Agent Cloud starts the Add OpenTelemetry Connection wizard.
  5. Enter a name for the connection.
  6. Click Generate Credentials.
    Agent Cloud creates the connection and displays the OTLP endpoint URL and bearer token.
  7. Copy the bearer token and store it as the RUBRIK_OTLP_TOKEN environment variable in your agent environment.
    Attention:
    Agent Cloud displays the bearer token only once. If you close the wizard without copying it, you must delete the connection and create a new one. Keeping the token in an environment variable, rather than in a configuration file, lets you commit the configuration safely.
  8. Click Finish.

Results

Agent Cloud is ready to receive OpenTelemetry traces from your instrumented agents.

What to do next

Instrument your AI agent to export traces to the connection endpoint. For setup instructions, see Supported OpenTelemetry frameworks.
