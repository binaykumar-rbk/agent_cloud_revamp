          • Rubrik AI gateway

            The Rubrik AI gateway is a Rubrik-hosted proxy between your custom agents and model providers. It records every prompt, response, and tool call, and blocks the ones that break a block policy before they reach the model or the agent.

          • LiteLLM

            If your custom agents already route their model traffic through a LiteLLM proxy, the Rubrik plugin for LiteLLM sends that traffic to Agent Cloud for recording and real-time policy enforcement, without changing your agents.

          • Manage gateway API keys

            Agent Cloud uses API keys to authenticate AI agents and a dual-key architecture — upstream keys and model gateway keys — to secure agent traffic.

          • OpenTelemetry

            An OpenTelemetry connection monitors AI agent activity from your existing agent frameworks and displays it as sessions in Agent Cloud.

        • Endpoint detection

          The Rubrik endpoint detection binary runs on employee devices to discover the AI agents installed there and the identities that use them, and, for supported agents, to capture their sessions and enforce policies in real time.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

How model gateways work

Model gateways are the fundamental infrastructure components that enable Agent Cloud to govern, monitor, and secure your AI agent interactions.

Model gateways function as an intelligent proxy layer, intercepting and processing requests between your custom AI agents and the LLMs they utilize.

Purpose and functionality

A model gateway acts as an intermediary that ensures visibility and control over AI traffic. Instead of your AI agents communicating directly with public LLM endpoints, such as OpenAI or Anthropic, they route their requests through the secure model gateway deployed within your infrastructure.
  • Governance and monitoring: The gateway captures detailed metadata about every interaction, including prompts, responses, and tool usage, and evaluates your policies inline.
  • Request routing: The gateway takes requests from your AI agent and forwards them to the appropriate LLM provider. It handles the authentication and connection details, abstracting this complexity away from the agent itself.
  • Connection requirement: Agent Cloud requires that custom AI agents that interact with LLMs through APIs such as OpenAI, Azure OpenAI, or Anthropic use the Rubrik AI gateway or your LiteLLM proxy, or export OpenTelemetry traces. Only gateways can block actions in real time.
Attention:
Agents that use the OpenAI API must use the Chat Completions API. The Responses API is not supported.
Attention:
Native integrations, such as Microsoft Copilot, connect directly to Agent Cloud through cloud-to-cloud APIs and do not require a customer-deployed gateway.

Architecture and data flow

The architecture of Agent Cloud utilizes a hybrid model designed to maintain data privacy and security.

Custom AI agents require that you deploy a model gateway and interact with an LLM using an API such as OpenAI, Azure OpenAI, or Anthropic.

When you create the model gateway, you specify the provider, model name, LLM API key, and an optional endpoint for each model that you want the model gateway to have access to. After deploying the model gateway, you must update any custom AI agents that use an LLM so it uses the model gateway as its LLM endpoint instead of the public or private endpoint of the native LLM. This enables the model gateway to take requests from the AI agent and forward them to the LLM. The model gateway simultaneously processes the data from the request and uses it for visibility and policy enforcement.

Model configuration and routing

Agent Cloud uses the model name to determine what model to use on the LLM. The model name specified in the AI agent must match the model names in the Agent Cloud model gateway. If they do not match, Agent Cloud issues an error.

For example, if you want to use the OpenAI gpt-4.1 model, the gateway model name specified in the Agent Cloud model gateway must be gpt-4.1. It is important that when the AI agent calls for a model, the value gpt-4.1 is specified in the agent, so the Agent Cloud model gateway knows which model to call in the LLM.

Authentication and security

Model gateways enable Agent Cloud to access and understand the interactions between agents and their LLMs.

When you create the model gateway, you specify the provider, model name, LLM API key, and an optional endpoint for each model that you want the model gateway to have access to. After deploying the model gateway, you must update any custom AI agents that use an LLM so it uses the model gateway as its LLM endpoint instead of the public or private endpoint of the native LLM. This enables the model gateway to take requests from the AI agent and forward them to the LLM. The model gateway simultaneously processes the data from the request and uses it for visibility and policy enforcement.

The model gateway uses the LLM API key to authenticate with the LLM. After creation, Agent Cloud creates a new API key that the AI agent uses to access the model router along with the model name. Agent Cloud supports adding multiple API Keys to the gateway. This can be used to control access to the Agent Cloud gateway by individuals or by groups.

You should never share upstream LLM API keys directly with AI agent developers. Instead, you should share only the Agent Cloud model gateway endpoint and API key with AI agent developers. This ensures that AI agents use the Agent Cloud model gateway for access.

Agent Cloud can configure LLMs with custom endpoints when enabling them in the model router. If you do not provide a custom endpoint, Agent Cloud uses the default LLM endpoint for a given model provider, if available.

Agent Cloud requires custom AI agents to use the OpenAI, Azure OpenAI, or Anthropic APIs to work with the model gateway. When configuring the model gateway for OpenAI, Azure OpenAI, and Anthropic, Agent Cloud uses their public endpoints if you do not specify an endpoint. Private customer endpoints for OpenAI, Azure OpenAI, and Anthropic can be used by filling in the Endpoints field when adding models to the gateway.

If an AI agent uses an OpenAI, Azure OpenAI, or Anthropic-compatible model, Agent Cloud requires that you specify a custom endpoint that points to the compatible LLM or SLM. You can also do this by using the Endpoints field when configuring the model in the gateway.

The model gateway generates a unique endpoint during creation. You must update your AI agents to use this model gateway endpoint instead of the default or custom endpoint of the LLM.
