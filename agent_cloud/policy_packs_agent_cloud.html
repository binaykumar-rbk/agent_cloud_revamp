      • Introduction to Agent Cloud
      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Choose your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Choose where it runs before you connect your AI providers and agents.

      • Connect your AI agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

        • How policies work

          A policy is a named rule with a severity that Agent Cloud evaluates against your agents, tools, and sessions. When agent activity breaks a policy, Agent Cloud records a violation or an alert and, depending on the policy's enforcement mode, can stop the action.

        • Plan your policy rollout

          Introduce policies in Monitor mode, review the alerts they produce, and move a policy to Block only after it behaves as you expect and only on connections that support blocking.

        • Enforcement modes

          A policy's enforcement mode determines what happens when agent activity breaks it: Monitor records an alert, and Block stops the action before it runs.

        • How blocking works

          A Block policy lets Agent Cloud stop an agent action before it takes effect, inline with the agent's own execution, instead of only flagging it afterward.

        • Agent Cloud system policies

          Agent Cloud includes multiple system policies. These policies are not enabled by default. You can enable them from the Policies page.

          A custom policy is a rule that you write in plain English. The Semantic AI Governance Engine (SAGE) turns it into a policy that it judges against agent activity by intent, not by matching keywords.

Agent Cloud policy packs

Agent Cloud policy packs are curated collections of system policies you can add to your Agent Cloud account to enable a focused set of controls for a specific risk area, compliance framework, or industry.

Policy packs let you enable a focused group of system policies as a single unit. Because some system policies can only Monitor, enabling a pack does not guarantee that every policy in it can block.

By default, Agent Cloud includes policy packs, which are groups of system policies that focus on detecting specific categories of risks, such as sensitive data exposure, prompt injection, unsafe code execution, and policy-violating model output.

Reviewing all the individual policies and deciding which apply to your account can be time-consuming, particularly for accounts that protect agents across more than one line of business. Policy packs solve this problem by grouping related system policies into named bundles that an administrator can add to or remove from an account as a single unit.

Policy pack behavior

Each policy pack contains a Rubrik-curated list of system policies that address a shared theme, such as data governance or content safety. When an administrator adds a pack to an account, Agent Cloud makes the member system policies available in the policy inventory and enables them by default. The administrator can then tune individual system policies, disable specific policies that do not apply, or add additional packs as the deployment grows.

Policy packs control which system policies are active in an account. They do not define new detection logic and they do not replace custom policies.
Attention:
A single policy can belong to more than one pack, so adding overlapping packs does not duplicate evaluations or alerts.

When to use policy packs

Policy packs scope the Agent Cloud policy inventory to the controls that matter for the workloads, regulatory environment, and risk profile of the account. Typical scenarios include the following:

  • Activating a baseline of common protections when onboarding a new RSC account to Agent Cloud.
  • Enabling a specific compliance framework, such as a responsible AI program or a data governance program, without selecting every policy individually.
  • Adding rules built for a specific industry, such as healthcare or banking, on an account whose AI agents work in that industry.
  • Layering additional protections, such as content safety or code execution safety, on top of the Essentials baseline category as new agent use cases come online.

Policy pack categories

Agent Cloud organizes policy packs into categories.

This table describes the policy pack categories included with Agent Cloud.
Category Description
Essentials A baseline pack that contains universal controls for data exposure, prompt injection, hallucination, and privilege escalation. Agent Cloud adds the Essentials pack to new accounts automatically so that core protections are in place from day one.
Security Packs that defend against threats to AI agent integrity and the data the AI agent can reach. This category includes packs for data exposure prevention, prompt security, agent permissions and boundaries, code execution safety, and tool and plugin integrity.
Compliance and governance Packs that align AI agent activity with audit, accountability, and responsible AI requirements. You can use these packs to support internal governance programs and external regulatory obligations.
Content safety A pack that blocks toxic, profane, harassing, or impersonating output from agents that interact with end users.
Industry Packs that target the regulatory and operational requirements of a specific industry, such as healthcare or financial services.

Managing policy packs

An Agent Cloud administrator can add or remove policy packs at any time from the policy packs catalog. Adding a pack makes its member policies visible in the policy inventory and enables them by default. Removing a pack hides the policies that no other active pack provides and stops Agent Cloud from generating new alerts for those policies. Existing alerts and historical evaluation data are preserved.
