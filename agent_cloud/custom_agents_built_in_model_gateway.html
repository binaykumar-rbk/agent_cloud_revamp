Rubrik AI gateway

The Rubrik AI gateway is a Rubrik-hosted proxy between your custom agents and model providers. It records every prompt, response, and tool call, and blocks the ones that break a block policy before they reach the model or the agent.

Your custom agents send requests to the gateway endpoint instead of to the model provider. You do not deploy or operate any gateway infrastructure.

Capabilities

This table lists what the Rubrik AI gateway supports.
Capability Support
Model providers OpenAI, Azure OpenAI, Anthropic, and compatible models at a custom endpoint
Discovery Agents, tools, sessions, identities
Session activity User prompts, agent responses, tool calls
Configuration violations Yes
Monitor Yes
Block User prompts, tool calls, tool responses, agent responses
Ask Not supported

Blocking fails open. If Agent Cloud cannot be reached or does not respond in time, the action proceeds. See Blocking limitations and fail-open behavior. For all connections, see Agent Cloud support matrix.

How the gateway works

The Rubrik AI gateway runs in the Rubrik-managed data plane. RSC provisions the gateway for your tenant the first time you create a gateway. Custom agents send requests to the gateway endpoint instead of to the native LLM endpoint. The gateway then:

  • Authenticates the agent using a gateway API key issued by Agent Cloud.
  • Records the request, response, and tool usage in the session log for the tenant.
  • Evaluates default and custom policies. Requests, tool calls, or responses that violate a policy are blocked before they reach the LLM or the calling agent.
  • Forwards approved requests to the LLM provider using the upstream API key and any custom endpoint that you configured for the requested model.

Because the gateway is Rubrik-managed, you do not deploy or operate any clusters, proxies, or storage to use it. The gateway, the log processor, and the object storage for session logs are all provisioned and maintained by RSC.

Supported model providers

The gateway accepts custom agent traffic that targets the following provider APIs:

This table describes the LLM providers that custom agents can target through the Rubrik AI gateway.
Provider Notes
OpenAI Uses the public OpenAI endpoint by default. You can supply a custom endpoint when you configure the model to target an OpenAI-compatible model that runs elsewhere.
Note:
When using the OpenAI API, ensure your custom agents use the standard Chat Completions API endpoint and not the Responses API endpoint. Agent Cloud does not support the Responses API endpoint.
Azure OpenAI Requires the Azure OpenAI endpoint URL, the API version, and the deployment names. Uses the upstream Azure API key to authenticate to the provider.
Anthropic Uses the public Anthropic endpoint by default. Supports a custom endpoint for private Anthropic deployments.
AWS Bedrock Requires the AWS access key, secret key, and region for the Bedrock account that hosts the target model.
Google Cloud Gemini Enterprise Requires the Google Cloud project identifier and service account credentials for the Gemini Enterprise project that hosts the target model.
Attention:
Native integrations, such as Microsoft Copilot Studio, connect directly to Agent Cloud through cloud-to-cloud APIs and do not use the Rubrik AI gateway.

Credential separation

The gateway separates the credentials that the gateway uses to reach the LLM from the credentials that the custom agent uses to reach the gateway:

  • The upstream API key is the API key issued by the LLM provider, such as OpenAI or Anthropic. You supply this key when you create the gateway. The gateway stores the key in the Rubrik-managed secrets store and uses it to authenticate to the provider. The upstream key is never returned to the user interface (UI) or to API responses after it is saved, and it is never sent to the custom agent.
  • The gateway API key is a credential that Agent Cloud generates for the gateway. You distribute the gateway API key to the developers who write the custom agent, and the agent uses it to authenticate to the gateway endpoint. You can issue multiple gateway API keys for the same gateway, so that you can control access per user or per group and revoke keys independently.

This separation ensures that AI agent developers do not handle the upstream provider keys, and that you can revoke an agent's access to the gateway without rotating the upstream credentials.

Endpoint and network access

Custom agents reach the gateway over HTTPS on port 443. The production gateway endpoint is https://aigateways.air-prod.predibase.com/. The AI agent and the infrastructure that runs it must have network access to this endpoint. If your network policy does not allow access by DNS name, contact your Rubrik account team for the IP addresses to add to your allowlist.

Responsibility boundary

The following table summarizes which components Rubrik operates and which components you operate when custom agents use the Rubrik AI gateway.

This table describes the responsibility boundary between Rubrik and the customer when custom agents use the Rubrik AI gateway.
Operated by Components
Rubrik The Agent Cloud control plane, the Rubrik AI gateway, the log processor, the Rubrik-managed object storage for session logs, and the secrets store for upstream API keys and gateway API keys.
You Your custom agents and the infrastructure on which they run, your accounts with the LLM providers, the upstream API keys and custom endpoints that you supply when you create gateways, and the network path between your agents and the gateway endpoint.
