      • Introduction to Agent Cloud
      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Choose your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Choose where it runs before you connect your AI providers and agents.

      • Connect your AI agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

        • Agent Cloud support matrix

          Find out what each Agent Cloud connection discovers, captures, and can block.

        • Enterprise AI platforms
          • Microsoft Copilot Studio deployed in Agent Cloud

            Agent Cloud reads Microsoft Copilot Studio agents and conversation transcripts through the Dataverse API and, when you enable tool blocking, intercepts tool calls in real time through Copilot Studio's external threat detection integration.

          • Microsoft 365 Copilot deployed in Agent Cloud

            Agent Cloud reads Microsoft 365 Copilot interactions through the Microsoft Graph API to discover the users and agents that use Copilot and to record their sessions.

          • Microsoft Foundry (new) deployed in Agent Cloud

            Agent Cloud reads Microsoft Foundry (new) agent activity from the Azure Application Insights resource linked to a Foundry project, through a service principal that you grant read access.

            • Microsoft Foundry (new) requirements for Agent Cloud

              Microsoft Foundry (new) integration requires specific Azure administrative roles, resource identifiers, and service principal permissions to enable agent discovery and log ingestion.

            • Deploying Microsoft Foundry (new) on Agent Cloud

              Deploy Microsoft Foundry (new) to Agent Cloud by establishing a secure service principal connection to your Azure tenant and mapping project resources.

          • Microsoft Foundry (classic) deployed in Agent Cloud

            Agent Cloud reads Microsoft Foundry (classic) agent activity from the Azure Application Insights resource linked to a Foundry project, through a service principal that you grant read access. Only instrumented agents are observed.

          • ChatGPT Enterprise deployed in Agent Cloud

            Agent Cloud polls OpenAI's Compliance API every 10 minutes to discover custom GPTs and ingest conversations and tool calls from a ChatGPT Enterprise workspace.

          • Claude Enterprise deployed in Agent Cloud

            Agent Cloud reads Claude Enterprise activity after the fact through Anthropic's Compliance API, using a read-only Compliance API key.

          • Google Cloud Gemini Enterprise in Agent Cloud

            Agent Cloud uses a Google Cloud service account that you create to discover agents and read their conversation sessions in a Google Cloud project, covering both Gemini Enterprise and Gemini Enterprise Agent Platform (Vertex AI Agent Engine).

          • AWS Bedrock Agents deployed in Agent Cloud

            Agent Cloud reads Amazon Bedrock model invocation logs from Amazon CloudWatch Logs or an Amazon S3 bucket, through an IAM role in your AWS account that Agent Cloud assumes.

          • Amazon Bedrock AgentCore deployed in Agent Cloud

            Agent Cloud reads the OpenTelemetry runtime logs that Amazon Bedrock AgentCore writes to Amazon CloudWatch, through an IAM role in your AWS account that Agent Cloud assumes.

        • Custom agents

          Custom agents that you build connect to Agent Cloud through the Rubrik AI gateway, through your existing LiteLLM proxy, or by exporting OpenTelemetry traces.

        • Endpoint detection

          The Rubrik endpoint detection binary runs on employee devices to discover the AI agents installed there and the identities that use them, and, for supported agents, to capture their sessions and enforce policies in real time.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

      • Administer Agent Cloud

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

Deploying Microsoft Foundry (new) on Agent Cloud

Deploy Microsoft Foundry (new) to Agent Cloud by establishing a secure service principal connection to your Azure tenant and mapping project resources.

Before you begin

Make sure:
  • You have reviewed Microsoft Foundry (new) requirements for Agent Cloud.
  • A Microsoft Foundry (New) project already exists in Microsoft Foundry (ai.azure.com).
  • An Application Insights resource is available in the same region as the Foundry project. If one does not exist, you can create one during this procedure.
  • The Azure account you will use has rights to grant administrator consent and to assign roles (for example, Owner or User Access Administrator) on the Application Insights resource.
Note:
Agent Cloud supports Microsoft Foundry (new), which this procedure refers to as Microsoft Foundry.

About this task

This task has four stages: Start the connection and grant consent, Connect Application Insights and record resource URIs, Assign the Log Analytics Reader role, and Complete the connection.

Deploying Microsoft Foundry enables Agent Cloud to ingest logs from Azure Application Insights, providing visibility and governance for AI agents within specific Foundry projects.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
Stage 1: Start the connection and grant consent
  1. In the top navigation bar, click Connectors.
  2. In the left panel, under Builder Platforms, click Microsoft Foundry.
  3. In the upper-right corner, click Add Connection.
    Agent Cloud opens the Connect to Microsoft Foundry wizard at the Authorize Connection step.
  4. Wait for the status banner to display Setup complete. Please sign in to your Microsoft account, then click Sign in with Microsoft.
    The account you use must have permission to grant administrator consent in the Azure tenant.
    A Microsoft sign-in window opens.
  5. In the Pick an account window, select the account for your Azure tenant, or click Use another account and sign in.
    Note:
    The account used for administrator consent sign-in must belong natively to the Azure tenant hosting the Foundry project rather than an external account added to the tenant.
  6. On the admin consent screen, review the permissions and click Accept.
    Granting consent registers an enterprise application named Rubrik Agent Cloud (Foundry) in your Azure tenant. The wizard resumes at the Configure Resources step.
  7. Click Next.
  8. In a browser, open Microsoft Foundry (ai.azure.com), open your Foundry project, and click Project Details in the left menu.
Stage 2: Connect Application Insights and record resource URIs
  1. Select the Connected resources tab and click Add connection.
  2. In the Choose a connection dialog, select Application Insights.
  3. In the Create a new connection dialog, select the Application Insights resource for this project, leave Auth type set to API Key, and click Add connection.
    The Application Insights resource appears on the Connected resources tab with the category AppInsights.
  4. On the Connected resources tab, locate the AppInsights entry and copy its Target value. Save it to a location you can access later.
    This is the Application Insights resource URI.
  5. On the same Admin page, under Basic configuration, locate Resource ID and click the copy icon. Save it to a location you can access later.
    This is the Foundry project resource URI.
  6. In the Azure portal, open the Application Insights resource connected to the Foundry project and click Access control (IAM) in the left menu.
Stage 3: Assign the Log Analytics Reader role
  1. Click Add and select Add role assignment.
  2. On the Role tab, search for and select Log Analytics Reader, then click Next.
  3. On the Members tab, set Assign access to to User, group, or service principal and click Select members.
  4. Search for Rubrik Agent Cloud, select Rubrik Agent Cloud (Foundry), and click Select.
  5. Click Review + assign, confirm the role and member details, and click Review + assign again to complete the assignment.
  6. In Agent Cloud, configure the connection details.
    FieldDescription
    Connection Name A descriptive name for this connection. Using the Foundry project name is recommended.
    Project Version The version of the Microsoft Foundry platform used by this project. Select Microsoft Foundry (New).
    Application Insights Resource URI The Application Insights Target value copied from the previous steps.
    Foundry Project Resource URI The Foundry project Resource ID copied from the previous steps.
Stage 4: Complete the connection
  1. Select the I have assigned the Log Analytics Reader role to the Agent Cloud (Foundry) application check box.
  2. Click Connect.

Results

The Microsoft Foundry project is connected and appears on the Microsoft Foundry Connectors page. Agent Cloud begins discovering agents and ingesting activity logs from the linked Application Insights instance. After the first sync completes, the Agents Discovered and Last Sync columns update to reflect discovered Foundry agents.
