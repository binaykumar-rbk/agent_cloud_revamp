Architecture for Agent Cloud deployed in an Azure VNet

When you deploy Agent Cloud in an Azure VNet, a hybrid architecture is used: a customer-managed data plane processes all sensitive AI agent traffic inside your Azure subscription, while RSC manages orchestration and policy from the control plane.

The Azure VNet architecture consists of:

  • A Agent Cloud control plane that is fully managed by Rubrik and handles all orchestration, business logic, policy definitions, and user interface (UI) components.
  • A data plane that is deployed in your Azure VNet and handles all sensitive operations and processing related to Agent Cloud. The data plane intercepts agent traffic, enforces policies in real time, and forwards enriched logs to the control plane. This ensures that your private data remains within your network boundaries and under your control.

Azure VNet architecture overview

The deployment model connects your Agent Cloud environment to the data plane inside your Azure VNet and enforces a strict separation of duties: RSC manages orchestration and policy, while you retain full control over data processing.

Data plane connection methods

The data plane is the integration point between your AI agents and Agent Cloud. You can connect AI agents to the data plane using one of three methods, depending on the type of AI agent and your existing infrastructure.

This table describes the methods available for connecting AI agents to the Agent Cloud data plane in your Azure VNet.
Method Description When to use
Rubrik AI gateway A Rubrik-provided model gateway that is deployed in your Azure VNet as part of the data plane. The gateway functions as a secure proxy that intercepts API requests to model providers such as OpenAI, Azure OpenAI, and Anthropic. The gateway manages upstream provider credentials and issues separate API keys to your developers. Use for custom AI agents when you do not already operate an AI gateway and want a managed deployment that Rubrik maintains.
Gateway plugin for existing customer gateways A plugin that you install in an AI gateway that you already operate, such as LiteLLM. The plugin forwards request and response data from your existing gateway to the data plane webhook for policy enforcement and logging. You configure the plugin with the data plane webhook URL and an API key. Use when you already operate an AI gateway and want to add Agent Cloud observability and governance without replacing your existing infrastructure.
Webhooks for cloud-based agent frameworks A direct webhook integration between a cloud agent framework and the data plane. The agent framework — such as Microsoft Copilot Studio, Microsoft Foundry, or AWS Bedrock AgentCore — sends event data directly to the data plane webhook endpoint using a POST request authenticated by an API key. Use for cloud or SaaS agents that do not route traffic through a model gateway but support sending event data to an external HTTP endpoint.

Data privacy and security mechanisms

The data plane architecture for Agent Cloud deployed in an Azure VNet is designed for security and data privacy. The mechanisms in the following table apply regardless of which data plane connection method you use.

This table describes how the Agent Cloud data plane implements specific mechanisms to ensure data security and sovereignty within your Azure environment.
Mechanism Description
Data flow All sensitive agent traffic related to Agent Cloud is routed to the data plane within your VNet. This data is processed locally and does not leave your Azure subscription.
Data storage Data is stored directly in a private Azure Blob Storage container within the Azure subscription that you manage.
Logging Requests and responses are logged to your private Azure Blob Storage container within the Azure subscription that you manage. By default, RSC deletes the requests and responses from the Blob Storage container after 60 days.
Private networking The entire infrastructure is designed to operate within your private network. You can connect agents to the data plane directly, or use Azure Private Link to establish a direct, private connection when you use multiple cloud accounts. All connections between your applications and the data plane use mTLS and HTTPS encryption.
Control plane communication All communication is initiated from the data plane to Agent Cloud, not from Agent Cloud to the data plane. The control plane receives only enriched metadata and policy evaluation results.
