Azure VNet deployment

Deploy the Agent Cloud data plane in your own Azure subscription, and review what the deployment creates, the architecture, data privacy mechanisms, best practices, your responsibilities, and the costs before you deploy.

The data plane processes agent traffic inside your Azure VNet, and you manage orchestration and policy from Agent Cloud. You give Agent Cloud access to deploy the required resources directly into your subscription, by running a Rubrik-provided Azure template.

When to use Azure VNet

You can deploy the Azure VNet when your custom AI agents and associated infrastructure are hosted in Azure. This minimizes latency by keeping the gateway close to your AI agents and enables you to leverage your existing Azure security configurations and compliance controls.

What the deployment creates

Deploying the Azure VNet data plane creates the following:
  • A resource group: This is the security boundary for all VPC data plane resources. This resource group is dedicated to RSC and must not contain other workloads.
  • A custom RBAC role: The Rubrik VPC Dataplane Provisioner role includes service-level wild card permissions scoped to the resource group. This role can manage Kubernetes, container registries, key vaults, networking, storage, and identity resources within the resource group, but cannot access any other location in your subscription.
  • A role assignment: Agent Cloud assigns this role to the Rubrik service principal with an RBAC condition that restricts role assignment write and delete permissions to pre-approved built-in roles. Agent Cloud cannot assign Owner, Contributor, or anything outside this allowlist.

Who does what

You run the Rubrik-provided Azure template in your subscription and send the deployment output to Rubrik. Rubrik Support then completes the final provisioning steps to connect your Azure VNet data plane to Agent Cloud.

Architecture

When you deploy Agent Cloud in an Azure VNet, a hybrid architecture is used. The control plane is fully managed by RSC and handles orchestration, business logic, policy definitions, and the User Interface (UI). The data plane runs in your Azure VNet. It intercepts agent traffic, enforces policies in real time, and sends enriched metadata and policy results to the control plane. The deployment model enforces a strict separation of duties: Rubrik manages orchestration and policy, while you retain full control over data processing. Your private data stays within your network boundaries and under your control.

Data plane connection methods

The data plane is the integration point between your AI agents and Agent Cloud. Your agents connect to it in one of these ways, depending on the type of agent and your existing infrastructure.

The following table describes the methods available for connecting AI agents to the Agent Cloud data plane in your Azure VNet.
Method Description Use when
Rubrik AI gateway A Rubrik-provided gateway that runs in your Azure VNet as part of the data plane. It acts as a secure proxy that intercepts API requests to model providers such as OpenAI, Azure OpenAI, and Anthropic, holds your upstream provider credentials, and issues separate API keys to your developers. Your custom agents do not already use a gateway, and you want a managed deployment that Rubrik maintains.
LiteLLM A plugin that you install in a LiteLLM gateway that you already operate. The plugin forwards request and response data from your gateway to the data plane webhook for policy enforcement and logging. You configure the plugin with the data plane webhook URL and an API key. Your custom agents already use a LiteLLM proxy, and you want to add Agent Cloud governance without replacing it.
API integrations For agents on enterprise AI platforms, Agent Cloud reads agent activity through the platform APIs. Your agents run on an enterprise AI platform.

Data privacy and security

The mechanisms in the following table apply regardless of which connection method you use.

The following table describes how the Agent Cloud data plane implements specific mechanisms to ensure data security and sovereignty within your Azure environment.
Mechanism Description
Data flow All sensitive agent traffic related to Agent Cloud is routed to the data plane within your VNet. This data is processed locally and does not leave your Azure subscription.
Data storage Data is stored directly in a private Azure Blob Storage container within the Azure subscription that you manage.
Logging Requests and responses are logged to your private Azure Blob Storage container within the Azure subscription that you manage. By default, RSC deletes the requests and responses from the Blob Storage container after 60 days.
Private networking The entire infrastructure is designed to operate within your private network. You can connect agents to the data plane directly, or use Azure Private Link to establish a direct, private connection when you use multiple cloud accounts. All connections between your applications and the data plane use mTLS and HTTPS encryption.
Control plane communication All communication is initiated from the data plane to Agent Cloud, not from Agent Cloud to the data plane. The control plane receives only enriched metadata and policy evaluation results.

Best practices

Rubrik recommends these best practices when you deploy Agent Cloud in an Azure VNet:

  • Assign administrative permissions: The user performing the onboarding commands must have the Owner or Global Administrator role on the tenant.
  • Use a dedicated resource group: Use a resource group that is dedicated to the data plane and does not contain other workloads.

Customer responsibilities

Deploying the data plane in your own Azure subscription gives you data control, and it also gives you specific responsibilities and risks to manage.

The following table describes the responsibilities and risks you must manage when deploying the Azure VNet infrastructure within your own Azure account.
Responsibilities and risks Description
Cost management You are responsible for all Azure costs that the data plane infrastructure incurs. Azure bills them directly to your Azure subscription. For the cost types and how to shut down the data plane, see Cost management.
Infrastructure and resource management The underlying infrastructure is in your account, and you are responsible for its management.
  • Service Quotas: You are responsible for ensuring your Azure account has sufficient service quotas, for example, specific GPU instances, for the environment to function correctly. Insufficient quotas cause workloads to fail.
  • Stack Integrity: You must not delete or manually alter the Azure resource group that provisions the environment. Doing so permanently breaks the connection from the stack to Agent Cloud and requires a full redeployment.
Security and access control Although the architecture is designed for security, you are responsible for the security posture of your Azure account.
  • Account Security: You are responsible for all security and access controls for the Azure account hosting the VPC, including managing the user permissions and access.
  • Metadata and Observability: While sensitive agent data and prompts remain in your VNet, system-level metadata, metrics, for example, specific GPU utilization, and debug logs are sent to Agent Cloud. This is necessary for platform health, monitoring, and observability. Be default, debug logs do not include sensitive data.

Cost management

Azure bills you directly for the data plane infrastructure. Costs fall into two types:

  • Base cost: The estimated base cost that covers the full cost to spin up the data plane in your environment, including an AKS cluster and Storage Account containers.
  • Compute usage cost: The variable cost incurred when CPU or GPU workloads process agent data.
Important:
Rubrik recommends that you monitor your Billing Console directly to view an accurate and current assessment of all costs associated with this environment.

To shut down the data plane, contact Rubrik Support and follow the deprovisioning process. Deleting the resources yourself can leave orphaned resources that continue to incur costs.
