          • Monitored agents
      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

MDM requirements

Requirements for deploying the Agent Cloud endpoint detection binary to user devices through a Mobile Device Management solution.

Supported MDM solutions

Agent Cloud deploys the endpoint detection binary to managed devices through a supported MDM solution. Agent Cloud supports Jamf Pro on macOS, and Microsoft Intune on macOS and Windows.

Endpoint device requirements

  • The device is enrolled in a supported MDM solution.
  • The device runs a supported operating system.
  • The device user has a home directory that the endpoint detection binary can scan for AI agent configuration files.
  • Outbound HTTPS connectivity that is established from the device to the Agent Cloud data plane webhook URL.
  • Outbound HTTPS connectivity that is established from the device to the Rubrik Artifactory URL that hosts the endpoint detection binary.

Binary requirements

  • The endpoint detection binary is a statically compiled Go binary distributed by Rubrik. Contact your Rubrik Account Executive or Solutions Engineer to obtain the executable for your operating system.
  • The macOS binary must be signed with the Rubrik Apple Developer ID and notarized by Apple.
  • The binary requires execute permissions on the device.

Credentials and connection requirements

Each MDM connection requires specific credentials, which are generated by Agent Cloud when you create the MDM connection.

This table lists the credentials required to authenticate the MDM connection with Agent Cloud.
Credential Description
Webhook URL The endpoint URL that receives agent detection data from the device.
API key The bearer token used to authenticate the device with Agent Cloud. The API key must be passed to the binary through the API_KEY environment variable to avoid exposing it in process listings.

Required runtime arguments

The MDM solution must invoke the endpoint detection binary with specific arguments on each device.

This table lists the runtime arguments accepted by the endpoint detection binary.
Argument Required Description
-endpoint Yes Webhook URL that receives agent detection data.
-hostname No Override for the auto-detected device hostname. Use the hostname value provided by the MDM solution.
-username No Override for the auto-detected device username. Use the username value provided by the MDM solution.
-install-claude-code-managed-settings No Installs the Claude Code PreToolUse hook into the system managed-settings directory. Mutually exclusive with -uninstall-claude-code-managed-settings.
-install-copilot-cli-policy No Installs the hook that enables tool call blocking for GitHub Copilot CLI.
-install-copilot-vscode-config No Installs the hook that enables tool call blocking for GitHub Copilot Chat in VS Code.
-managed-settings-binary-path No The absolute path where the binary is installed. Hooks run the binary from this path on every tool call, so it must be a persistent location.
-uninstall-claude-code-managed-settings No Removes the Claude Code PreToolUse hook installed by the binary. Mutually exclusive with -install-claude-code-managed-settings.

Claude Code managed settings install paths

When the binary is invoked with the -install-claude-code-managed-settings argument, it writes the hook file to an operating-system-specific path. The MDM solution must invoke the binary with sufficient privileges to write to these paths.

This table lists the operating-system-specific paths that Agent Cloud uses to install the Claude Code managed-settings hook file.
Operating system Path
macOS /Library/Application Support/ClaudeCode/managed-settings.d/90-rubrik.json
Linux /etc/claude-code/managed-settings.d/90-rubrik.json
Windows C:\Program Files\ClaudeCode\managed-settings.d\90-rubrik.json

Jamf Pro requirements

For Jamf Pro deployments, the endpoint detection binary is delivered through a Jamf policy script that downloads the binary from Rubrik Artifactory and runs it on each device. The Jamf policy must provide the following positional parameters.

This table lists the positional parameters required by the Jamf Pro policy script.
Parameter Source Description
$1 Reserved by Jamf Mount point. Not used by the script.
$2 Reserved by Jamf Computer name. Used as the device hostname.
$3 Reserved by Jamf Username. Used as the device username.
$4 User-defined Webhook URL for agent detection.
$5 User-defined API key. Passed to the binary through the API_KEY environment variable.
$6 User-defined Artifactory URL that hosts the endpoint detection binary.
$7 User-defined Whether to install the Claude Code managed-settings hook. Accepted truthy values are:
  • true
  • True
  • TRUE
  • 1
  • yes
  • YES
  • Yes

Any other value or omission skips installing the Claude Code managed-settings hook from the Jamf Pro policy.
$9 User-defined Whether to install the GitHub Copilot CLI hook. Accepts the same values as $7.
$10 User-defined Whether to install the GitHub Copilot VS Code hook. Accepts the same values as $7. The parameters are positional, so to enable a later hook alone, pass the earlier ones as empty strings. When any hook is enabled, the script copies the binary to a persistent, root-owned location so that the hooks can run it.
