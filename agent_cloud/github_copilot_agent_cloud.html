GitHub Copilot on endpoints

Agent Cloud captures GitHub Copilot sessions from the device and, on macOS and Linux, blocks Copilot tool calls in real time through hooks that the endpoint detection binary installs.

This topic covers GitHub Copilot, the coding assistant. It does not cover Microsoft 365 Copilot or Microsoft Copilot Studio, which connect through their own connections.

Copilot form factors

Copilot runs in several forms, and they do not share enforcement.

This table lists the GitHub Copilot form factors and what Agent Cloud captures and enforces for each.
Form factorSession captureBlocking
Copilot Chat in VS Code (the Copilot Chat extension)Prompts, responses, and tool callsTool calls, through a hook that the binary installs in the user's Copilot hooks folder. The user owns this file and can edit or delete it; the next MDM run restores it.
Copilot CLI (the standalone copilot command)Prompts, responses, and tool callsTool calls, through a root-owned system policy file that users cannot remove or disable.
VS Code's Local agentNot confirmedTool calls, through the VS Code hook only. This agent does not read the Copilot CLI policy file, so install the VS Code hook to cover it.
Copilot for JetBrainsPrompts, responses, and tool callsNo

How Agent Cloud integrates with Copilot

  • Discovery: reports which Copilot surfaces are installed, the VS Code extensions and the language-model tools they provide, and the Copilot CLI's MCP servers.
  • Session capture: reads Copilot's session data from the device and uploads new activity on each run.
  • Real-time enforcement: before Copilot runs a tool, the hook sends the call to Agent Cloud, which allows or blocks it.

Copilot's prompt event is a notification only, so Agent Cloud cannot block or change a Copilot prompt. Copilot tool results are not redacted.

Deploy the hooks

Deploy the endpoint detection binary with your MDM solution, and enable the hooks for the Copilot surfaces you use. In Jamf Pro, set parameter $9 to true for the Copilot CLI and $10 for Copilot in VS Code. When you run the binary yourself, pass -install-copilot-cli-policy and -install-copilot-vscode-config. For details, see MDM requirements.

Limitations

  • Copilot blocking is supported on macOS and Linux. On Windows, Copilot sessions are captured but tool calls are not blocked.
  • Copilot loads hooks when it starts. A Copilot session that was already running when the hooks were installed is not enforced until it restarts.
  • Blocking fails open: if Agent Cloud does not respond, the tool call runs. If the Copilot CLI cannot run its hook at all, for example because the binary is missing, it blocks every tool call until the next MDM run repairs the hook. In VS Code, a failed hook falls back to VS Code's own approval prompt instead. For details, see Blocking limitations and fail-open behavior.
  • In VS Code, when Agent Cloud allows a tool call, the call is approved without VS Code's own confirmation prompt.
