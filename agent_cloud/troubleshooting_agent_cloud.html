    • Agent Cloud with RSC

      Agent Cloud with RSC provides a comprehensive solution for discovering AI agents in your environment, understanding which tools they have access to, detecting risky actions they perform on your data and configurations, and rewinding unauthorized changes without downtime.

      • Introduction to Agent Cloud
      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Choose your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Choose where it runs before you connect your AI providers and agents.

      • Connect your AI agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

      • Administer Agent Cloud

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

        • Access control for Agent Cloud

          Agent Cloud separates seeing what it found from reading what agents said. Session content is the most sensitive data that Agent Cloud holds, so viewing it requires its own privilege, which no built-in role includes.

        • Event log and audit log

          The event log records platform activity in Agent Cloud, such as policy updates and connection changes. The audit log records who did what. Open both from the Events menu.

        • Responsibilities by role

          Who is responsible for each part of an Agent Cloud deployment: the customer, Professional Services, or Rubrik Support.

          Follow these practices to roll out Agent Cloud safely and to get the most accurate inventory, monitoring, and enforcement for your agents.

Troubleshooting Agent Cloud

Find the likely cause and the first thing to check when an agent, session, block, or rewind does not behave as you expect.

This topic lists the causes that the documentation states for common symptoms. If the check does not resolve the problem, contact Rubrik Support.

This table lists common symptoms, their likely causes, what to check, and where to read more.
SymptomLikely causeWhat to checkRead
A connection or agent does not appear in the inventory.The agent has not run since you created the connection, or the connection setup is incomplete.Run the agent, then check the connection list and the AI inventory. For an endpoint agent, confirm that it appears as active on the Dashboard.Verifying your Agent Cloud setup; AI inventory
No session appears.Activity can take time to appear. For ChatGPT Enterprise, OpenAI may not have enabled Compliance API access, or the workspace may have no recent activity. For endpoint agents, the session appears after the next run of the binary.Wait for the typical time, run the agent again, and check the Sessions page. If nothing appears after 30 minutes for ChatGPT Enterprise, check the Compliance API access, then contact Rubrik Support.Verifying your Agent Cloud setup; Sessions and actions
A Block policy did not block an action.The connection cannot block, or cannot block that message type. The message type was not selected for blocking. The decision timed out and blocking failed open. The agent reached the provider or tool directly. The oversized-prompt exception does not apply to these.Check the support matrix for the connection. Check the message types that the policy blocks. Remember that a policy alert is still recorded.Blocking limitations and fail-open behavior; Agent Cloud support matrix
An action was blocked but no alert is visible yet.The alert is created when the session is processed, so it appears after a delay.Wait, then search the Alerts page for the blocking reference ID in the refusal message. A blocked action shows a Blocked chip.What happens when an action is blocked
Rewind cannot proceed.Rubrik does not protect the object, no complete snapshot exists within seven days before the action, or the workload is not supported.Confirm that the object is protected and that a qualifying snapshot exists. Check the supported workloads and the workload-specific requirements.Rewind AI agent changes with Agent Cloud; Supported workloads for Agent Rewind
Users cannot see session content.No built-in role includes View Session Timelines and Summaries.Create a custom role with the privilege, or add it to an existing custom role.Granting session viewing access; Access control for Agent Cloud
A custom agent cannot reach the Rubrik AI gateway.The network path to the gateway endpoint on port 443 is blocked, or your network policy does not allow access by DNS name.Allow HTTPS on port 443 to the gateway endpoint. If DNS names are not allowed, contact your Rubrik account team for IP addresses.Rubrik AI gateway
The data plane deployment in my AWS or Azure account is failing.The account may lack the service quotas that the environment needs, or the stack or resource group was changed or deleted.Check service quotas. Do not delete or alter the CloudFormation stack or the Azure resource group. A deleted stack requires a full redeployment. Contact Rubrik Support.Customer responsibilities for AWS VPC deployment; Customer responsibilities for Azure VNet
