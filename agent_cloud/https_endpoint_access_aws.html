      • Introduction to Agent Cloud
      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Choose your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Choose where it runs before you connect your AI providers and agents.

        • Region support for Agent Cloud

          Agent Cloud supports regions across SaaS, AWS, and Azure deployments.

        • Provision SaaS infrastructure

          The SaaS deployment of Agent Cloud uses a Rubrik-managed data plane that RSC provisions automatically when you onboard your AI provider connections. Traffic between your SaaS-based AI agents and Agent Cloud is brokered through this dedicated Rubrik-managed infrastructure.

        • AWS VPC deployment

          Deploying AWS VPC in Agent Cloud involves provisioning the necessary infrastructure directly within your AWS account to establish a dedicated data plane.

          • Architecture for Agent Cloud deployed in an AWS VPC

            When you deploy Agent Cloud in an AWS VPC, a hybrid architecture is used: a user-managed data plane processes all sensitive AI agent traffic inside your AWS account, while Agent Cloud manages orchestration and policy from the control plane.

          • Best practices for deploying Agent Cloud in an AWS VPC

            Rubrik recommends that you follow these best practices when you deploy Agent Cloud in an AWS VPC.

          • Customer responsibilities for AWS VPC deployment

            Deploying the model gateway infrastructure within your own AWS account provides data control, but also introduces specific responsibilities and risks that you must manage.

          • Cost management for AWS VPC deployment

            You will be billed for all resources for the model gateway infrastructure directly using your AWS Billing Console.

          • Deploying AWS VPC on Agent Cloud

            Deploy AWS VPC infrastructure in your AWS account to enable Agent Cloud. Rubrik Support completes the final configuration steps.

          • Configuring AWS PrivateLink

            Configure AWS PrivateLink to create a private endpoint in your workload VPC using the AWS UI.

          • Configuring AWS PrivateLink using the AWS CLI

            Configure AWS PrivateLink to create a private endpoint in your VPC using the AWS CLI.

          • HTTPS endpoint access for AWS

            When you have established network connectivity, Rubrik configures an HTTPS endpoint for your dataplane.

        • Azure VNet deployment

          In an Azure VNet deployment, the Agent Cloud data plane runs in your own Azure subscription, so prompts, responses, and other agent content stay inside your cloud boundary.

      • Connect your AI agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

      • Administer Agent Cloud

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

HTTPS endpoint access for AWS

When you have established network connectivity, Rubrik configures an HTTPS endpoint for your dataplane.

This is the only URL your applications should use. You should never connect to raw IPs directly. The HTTPS endpoint ensures end-to-end TLS encryption from your application to the Istio ingress gateway inside the EKS cluster.

You provide Rubrik the DNS target, which is the VPC endpoint DNS name. Rubrik then creates a CNAME record on a Rubrik-owned domain. The format is <your-env>.direct.<env>.predibase.com.

This is your DNS target.

Rubrik provisions and maintains a TLS certificate for your endpoint. The certificate is served by the Istio ingress gateway inside your EKS cluster, so TLS terminates at the NLB on the cluster, not at an external endpoint. This ensures end-to-end encryption over your private network path.

Rubrik provides you the direct ingress hostname, which you must use this for all API calls.

The hostname follows this pattern. 
env-abc123-westus2.direct.staging.predibase.com
