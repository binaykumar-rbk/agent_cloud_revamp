        • Observability

          Describes how to send OpenTelemetry traces from your agent frameworks to Agent Cloud.

          The Rubrik endpoint detection binary runs on employee devices to discover the AI agents installed there and the identities that use them, and, for supported agents, to capture their sessions and enforce policies in real time.

          • Endpoint detection requirements

            Requirements for running the Rubrik endpoint detection binary on employee devices: the requirements that apply to every deployment, and the additional requirements for MDM deployments and for manual installation.

          • Deploy with MDM

            Mobile Device Management (MDM) integrates endpoint management data into Agent Cloud for visibility into AI agent identities and the devices they run on, and it deploys the endpoint detection binary to employee devices through Jamf Pro or Microsoft Intune.

          • Install manually

            Describes how to install the endpoint detection binary manually on an individual macOS, Windows, or Linux device.

          • Verifying endpoint monitoring and enforcement

            Confirm that Agent Cloud captures an endpoint agent's activity from a device, and that real-time blocking takes effect when you enable a block policy.

          • Uninstalling the endpoint detection binary

            Remove the Claude Code managed settings and the recurring schedule installed by the Rubrik endpoint detection binary so Agent Cloud no longer monitors or enforces policies in Claude Code on the device.

          • Monitored agents

            Describes the coding and desktop agents on employee devices for which Agent Cloud captures sessions, such as Claude Code and GitHub Copilot.

            • Claude Code

              Agent Cloud captures Claude Code sessions from the device and enforces policies on Claude Code prompts, tool calls, and tool results in real time, through hooks in Claude Code's managed settings.

            • GitHub Copilot

              Agent Cloud captures GitHub Copilot sessions from the device and, on macOS and Linux, blocks Copilot tool calls in real time through hooks that the endpoint detection binary installs.

            • Claude Cowork

              Agent Cloud captures and enforces policies on Claude Cowork sessions that run on the user's computer. Cowork sessions that run in Anthropic's cloud are not visible to endpoint detection.

            • Codex (Early access)

              Agent Cloud captures OpenAI Codex sessions from the device and enforces policies on Codex prompts, tool calls, and tool results in real time, through hooks in Codex's managed configuration.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Govern and control

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind agent actions

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. You can start a rewind from the Sessions page, or from any page that displays the action or alert detail tray. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

Adding MCP servers to the gateway

Add an MCP server to your MCP gateway and choose who can access it, so that agents reach the server through the gateway's endpoint.

Before you begin

  • An MCP gateway with the status Connected. You cannot add servers to a gateway that is still connecting or that failed to connect.
  • The URL of an MCP server that uses the Streamable HTTP transport.
  • If the server uses OAuth: permission to register an OAuth app with the server's provider, and the provider's OAuth discovery URL.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Click Inventory > MCP Servers, and then click Add MCP Server.
    The Add an MCP Server wizard opens.
  4. Under Add to an MCP Gateway, select the gateway.
  5. Under MCP Server Details, enter the details.
    This table describes the MCP server details.
    Field Value
    Server Name A name for the server.
    Server URL The server's Streamable HTTP endpoint.
    Namespace Prefix A prefix added to the server's tool names, for example yourprefix_getIssue, which keeps tool names unique across the servers behind a gateway.
    Auth type OAuth, recommended for most servers, or Unprotected, for open servers or testing only.
  6. If you selected OAuth, register an OAuth client with the server's provider.
    1. Copy the Redirect URL that Agent Cloud generates, and add it as the authorization callback URL in an OAuth app that you register with the provider.
    2. Enter the app's Client ID and Client Secret, the provider's Well-Known URL, and the Scopes to request.
    The redirect URL stays the same if you later change the namespace prefix, so you do not need to update the OAuth app.
  7. Under MCP Server Access, choose who can use the server.
    • All users: Everyone in your organization.
    • Specific users and groups: Only the users and groups that you select. You can also exclude specific users or groups.
    • No one: No access yet. You can grant access later.
    • Custom access: A rule written in Rego, the Open Policy Agent policy language. The rule must start with package orchestrator.
    For more information, see MCP access policies (Early access).
  8. Click Add.
    The server is added, and the gateway is redeployed to include it.

Results

When the deploy finishes, agents that use the gateway endpoint can reach the server, subject to its access policy. Point each agent's MCP configuration at the gateway endpoint URL rather than at the server directly.
