      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Choose your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Choose where it runs before you connect your AI providers and agents.

      • Connect your AI agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

        • Agent Cloud support matrix

          Find out what each Agent Cloud connection discovers, captures, and can block.

        • Enterprise AI platforms
        • Custom agents

          Custom agents that you build connect to Agent Cloud through the Rubrik AI gateway, through your existing LiteLLM proxy, or by exporting OpenTelemetry traces.

        • Endpoint detection

          The Rubrik endpoint detection binary runs on employee devices to discover the AI agents installed there and the identities that use them, and, for supported agents, to capture their sessions and enforce policies in real time.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

      • Administer Agent Cloud

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

Agent Cloud support matrix

Find out what each Agent Cloud connection discovers, captures, and can block.

Overview

Agent Cloud supports multiple platform integrations, each with different capabilities for agent discovery, session activity, configuration violations, monitoring alerts, blocking, and ask. The sections in this matrix match the categories on the Connectors page: Builder Platforms, Enterprise Apps, AI Gateways, Observability, and Endpoint Detection.

Most connections cannot block. Where a connection cannot block, block policies behave like monitor policies. For how blocking works, see How blocking works.

Column definitions

This table describes the alerting and policy enforcement columns in the support matrix tables.
ColumnDescription
ViolationsIndicates whether Agent Cloud can generate configuration violation alerts, which are raised when an AI agent's configuration, such as its tools or settings, violates a configured policy.
MonitorIndicates whether Agent Cloud can generate alerts based on activity that Agent Cloud observes in agent sessions. For example, Agent Cloud can flag anomalous prompts, responses, or tool calls as they happen.
BlockIndicates which message types Agent Cloud can intercept and block before they run, rather than logging or alerting afterward. The possible message types are User prompts, Tool calls, Tool responses, and Agent responses. Where a connection cannot block, block policies behave like monitor policies and blocking fails open.
AskIndicates whether the integration can hand an action to the client's own approval prompt before the action runs. Agent Cloud records that a prompt was issued but does not learn the decision of the user. Where ask is not supported, ask policies fall back to monitoring or blocking, as configured on the policy. Ask support is account-dependent.

Related concepts

    A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.
  • How blocking works
    A Block policy lets Agent Cloud stop an agent action before it takes effect, inline with the agent's own execution, instead of only flagging it afterward.

    Early access features are Agent Cloud features that are available before general availability to organizations that opt in.
