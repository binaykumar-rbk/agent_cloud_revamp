        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Choose your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Choose where it runs before you connect your AI providers and agents.

      • Connect your AI agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

How Agent Cloud works

Agent Cloud splits its work between a control plane in RSC and a data plane that processes agent traffic, and it connects to your agents in one of four ways.

Control plane and data plane

  • Control plane: Runs in RSC. It hosts the user interface, stores policy definitions, and orchestrates connections, policy evaluation, and Agent Rewind.
  • Data plane: Processes agent traffic and session content, such as prompts, responses, and tool calls. You choose where the data plane runs: as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. For more information, see Choose your data plane.

Ways to connect your agents

How Agent Cloud captures an agent's activity depends on where the agent runs:

  • API integrations: For agents on enterprise AI platforms, such as Microsoft Copilot Studio, ChatGPT Enterprise, or Amazon Bedrock. Agent Cloud reads agents and sessions through the platform's APIs.
  • Rubrik AI gateway or LiteLLM: For custom agents that call model providers directly. The agent sends its model traffic through the Rubrik AI gateway, or through your existing LiteLLM proxy with the Rubrik plugin, so that Agent Cloud can record and block it in real time.
  • Endpoint detection: For coding and desktop agents on employee devices, such as Claude Code. You deploy the Rubrik endpoint detection binary with your mobile device management (MDM) solution.
  • OpenTelemetry: For agents built on frameworks that emit OpenTelemetry traces.

For help choosing, see Choose how to connect your agents. For what each connection discovers, captures, and can enforce, see Agent Cloud support matrix.

Some capabilities are available as early access features. For more information, see Early access features.

From activity to action

After an agent is connected, Agent Cloud adds the agent and its tools to the inventory and records each session. Policies are evaluated against that activity: a block policy can stop an action in real time on connections that support blocking, and every policy produces an alert or a violation when it is broken. When an agent action damages data that Rubrik protects, Agent Rewind restores the affected objects.
