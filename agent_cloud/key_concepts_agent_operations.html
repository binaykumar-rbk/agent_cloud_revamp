      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Deploy your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Decide where it runs before you connect your AI providers and agents.

      • Connect your agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Govern and control

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind agent actions

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. You can start a rewind from the Sessions page, or from any page that displays the action or alert detail tray. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

        Control who can view and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

Key concepts for Agent Cloud

Information about the core components of Agent Cloud and how these components work together to provide observability, security, and remediation for your AI infrastructure.

Understanding the core components of Agent Cloud is essential to successfully deploy and manage your AI infrastructure. Agent Cloud provides visibility into AI agent behavior, enabling you to monitor actions, enforce governance, and recover from data errors.

About Agent Cloud

Agent Cloud is a governance and observability platform within RSC. Unlike standard logging tools, Agent Cloud is designed specifically for agentic AI, which are AI systems that can autonomously run tasks and modify data. Agent Cloud captures the full context of the activity of an agent, including input prompts, memory context, prompting chains, and tool usage. This visibility enables you to detect risky behaviors and trace data errors back to their root causes.

Cloud agents

Cloud or SaaS providers typically supply cloud agents. These agents sometimes require custom integrations with the Agent Cloud webhook framework to collect data.

Endpoint agents

Endpoint agents are AI agents that run on desktops or laptops. The Agent Cloud endpoint detection binary runs on the device to retrieve data from these agents.

Hybrid architecture

Agent Cloud uses a hybrid deployment model designed to maintain strict data privacy and security. This architecture splits responsibilities between the Rubrik control plane and your local cloud environment.

  • Agent Cloud: This control plane manages the user interface, orchestration, and policy definitions. It handles metadata but does not process sensitive payload data.
  • Customer data plane: Deployed in your own cloud account (for example, an AWS VPC or Azure subscription), this layer contains the model gateways and private storage. All sensitive agent traffic, such as prompts and responses, is processed and logged locally within this boundary, ensuring that private data does not leave your environment.

Model gateways

A model gateway is the infrastructure component that sits between your custom AI agents and the Large Language Models (LLMs) that these agents use. This gateway functions as a secure proxy, intercepting all API requests to providers such as OpenAI, Azure OpenAI, or Anthropic.

You use model gateways only with custom AI agents, which are AI agents that you build to perform specific tasks autonomously.

Agent Cloud also supports native integrations such as Microsoft Copilot Studio, which have AI built in rather than added through a plugin, and Bring-Your-Own (BYO) gateways, which let you use your own API keys and infrastructure to manage, monitor, and secure AI traffic.

  • Role: The model gateway processes request data locally for monitoring and policy enforcement before forwarding it to the LLM.
  • Requirement: Deploying a model gateway is mandatory for custom AI agents to ensure their traffic is monitored. Native integrations, such as Microsoft Copilot Studio, connect directly to Agent Cloud and do not require a customer-deployed model gateway.
  • Authentication: The model gateway manages authentication with the LLM provider using upstream API keys, while issuing separate gateway API keys to your developers. This ensures that your sensitive provider credentials are not exposed directly to agent code.

Policies

Policies are the rules that govern AI agent actions. Agent Cloud monitors agent traffic against these policies to prevent data loss and security violations. Agent Cloud includes system policies and custom policies:

  • System policies: Policies that are included with Agent Cloud. You do not need to add them, but you can configure them.
  • Custom policies: You can define custom policies using natural language. For example, Do not allow Personally Identifiable Information (PII) to be sent to the LLM. An AI Judge interprets these descriptions to enforce complex governance rules.

Rewind errors

Rewind is a remediation capability of Agent Cloud that enables you to reverse specific data changes made by an AI agent without rolling back the entire system. Agent Cloud maps every tool use, such as an API call that deletes a file, to specific timestamped events. Therefore, Agent Cloud can identify the precise moment an error occurred. You can use the Rewind feature to undo granular transactions caused by agent hallucinations or logic errors, restoring data to its previous valid state.

Tools

In the context of Agent Cloud, a tool refers to the specific function, API, or capability that an AI agent invokes to perform a task. A delete_file API or a query_database function is considered a tool. Agent Cloud discovers these tools and enables you to authorize or restrict their usage to reduce risk.

MCP servers

Model Context Protocol (MCP) is an open standard for connecting AI agents to external tools and data sources. An MCP server exposes tools, resources, and prompts that an AI agent can call during a session. In Agent Cloud, the MCP Servers Inventory page displays the MCP servers that Agent Cloud discovers on endpoints running Claude Code. The inventory also has an Added tab for the MCP servers that you add to an MCP gateway. The MCP gateway is an early access feature. For more information, see MCP gateway (Early access).

Agent Cloud collects MCP server configuration through Mobile Device Management (MDM).

Webhooks

A webhook is a user-defined HTTP callback that one system uses to push event data to another system in near real time. In Agent Cloud, webhooks are used to connect to cloud agents when model gateways are not available.
