      • Choose your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Choose where it runs before you connect your AI providers and agents.

      • Connect your AI agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

      • Administer Agent Cloud

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

Choose how to connect your agents

The connection that you use for an agent depends on where the agent runs, and it determines whether Agent Cloud can block the agent's actions in real time.

Important:
Blocking fails open: if Agent Cloud cannot reach a decision in time, the action proceeds. Most connections cannot block at all. An agent that reaches a model provider or tool directly, outside a connection that enforces policy, is not blocked. For more information, see Blocking limitations and fail-open behavior.

Custom agents that already use a LiteLLM proxy How the LiteLLM plugin works User prompts, tool calls, tool responses, and agent responses
Agents built on a framework instrumented with OpenTelemetry OpenTelemetry No
Coding and desktop agents on employee devices Endpoint detection Depends on the agent. For example, Claude Code supports blocking user prompts, tool calls, and tool responses, and some agents are detection only.

When you need a gateway

Custom agents need either the Rubrik AI gateway or a LiteLLM proxy with the Rubrik plugin. Custom agents call model providers, such as OpenAI, Azure OpenAI, or Anthropic, through an API, and the gateway is where Agent Cloud records and controls that traffic. Use LiteLLM if your agents already route their model traffic through LiteLLM; otherwise, use the Rubrik AI gateway.

Agents on enterprise AI platforms do not need a gateway. Agent Cloud connects to those platforms directly through their APIs.
