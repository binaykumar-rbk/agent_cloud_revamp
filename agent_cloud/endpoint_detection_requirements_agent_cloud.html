      • Rewind agent actions

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. You can start a rewind from the Sessions page, or from any page that displays the action or alert detail tray. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

Device requirements

The following table lists the requirements that a device must meet, and the deployment methods that each requirement applies to.
Requirement Details Applies to
Operating system macOS (universal), Windows (amd64), or Linux (amd64). All deployments
Home directory A user home directory that the binary can scan for agent configuration files. All deployments
Network access Outbound HTTPS access from the device to the endpoint URL of your connection. No inbound connectivity to the device is required. All deployments
Administrative rights Administrative rights for the one-time install of agent hooks: sudo on macOS and Linux, or an elevated PowerShell session on Windows. MDM solutions run the binary with the required privileges. All deployments
MDM enrollment The device is enrolled in a supported MDM solution. For more information, see Additional requirements for MDM deployments. MDM deployments
Artifactory access Outbound HTTPS access from the device to the Rubrik Artifactory URL that hosts the binary. Jamf Pro
Scheduler cron on macOS and Linux, or Task Scheduler on Windows. Manual installation
Claude Code Claude Code is installed on the device, to monitor and enforce policies for Claude Code. To install Claude Code, see Claude Code. Manual installation

Binary

  • The endpoint detection binary is a statically compiled Go binary that Rubrik distributes. Contact your Rubrik Account Executive or Solutions Engineer to obtain the executable for your operating system.
  • The macOS binary must be signed with the Rubrik Apple Developer ID and notarized by Apple.
  • The binary requires execute permission on the device.
  • You can save the binary in any location, such as Downloads, Documents, or a custom folder. Note the absolute path to the binary. You use that path when you deploy it.
  • The administrator who creates the connection distributes the correct binary for each operating system to each user, or to the MDM solution.
The following table lists the endpoint detection binary file name for each platform.
Platform Binary file name
macOS (universal) racdiscovery-darwin-universal
Linux (amd64) racdiscovery-linux-amd64
Windows (amd64) racdiscovery-windows-amd64.exe

Credentials

You get an endpoint URL and an API key when you create the connection. For more information, see Connecting Mobile Device Management. Pass the API key to the binary through the API_KEY environment variable, never as a command-line argument, so that it is not exposed in process listings.

If you did not create the connection, get the binary, the endpoint URL, and the API key from the administrator who did.

The following table lists the credentials that authenticate the endpoint detection binary with Agent Cloud.
Credential Description
Endpoint URL The URL that receives agent detection data from the device. The connection wizard calls this value the webhook URL. Pass it with the -endpoint argument.
API key The bearer token that authenticates the device with Agent Cloud. The API key must be passed to the binary through the API_KEY environment variable to avoid exposing it in process listings.

Command-line arguments

The binary accepts these arguments, whether you run it from an MDM solution, a script, or a scheduled task. An uninstall run removes the hooks and exits without scanning. You cannot combine install and uninstall arguments in one run.

The following table lists the runtime arguments accepted by the endpoint detection binary.
Argument Required Description
-endpoint Yes The endpoint URL of your connection.
-hostname No Override for the auto-detected device hostname. For example, use the hostname value that your MDM solution provides.
-username No Override for the auto-detected device username. For example, use the username value that your MDM solution provides.
-install-claude-code-managed-settings No Installs the Claude Code PreToolUse hook into the system managed-settings directory. Mutually exclusive with -uninstall-claude-code-managed-settings.
-install-codex-managed-config No Installs the hooks that enable real-time enforcement for Codex (early access).
-install-copilot-cli-policy No Installs the hook that enables tool call blocking for GitHub Copilot CLI.
-install-copilot-vscode-config No Installs the hook that enables tool call blocking for GitHub Copilot Chat in VS Code.
-managed-settings-binary-path No The absolute path where the binary is installed. Hooks run the binary from this path on every tool call, so it must be a persistent location.
-uninstall-claude-code-managed-settings No Removes the Claude Code PreToolUse hook installed by the binary. Mutually exclusive with -install-claude-code-managed-settings.
-uninstall-codex-managed-config No Removes the Codex hooks installed by the binary.
-uninstall-copilot-cli-policy No Removes the hook that enables tool call blocking for GitHub Copilot CLI.
-uninstall-copilot-vscode-config No Removes the hook that enables tool call blocking for GitHub Copilot Chat in VS Code.
-version No Prints the binary version and exits.

Claude Code hook location

When you run the binary with the -install-claude-code-managed-settings argument, it writes the hook file to an operating-system-specific path. Run the binary with sufficient privileges to write to these paths.

The following table lists the operating-system-specific paths that Agent Cloud uses to install the Claude Code managed-settings hook file.
Operating system Path
macOS /Library/Application Support/ClaudeCode/managed-settings.d/90-rubrik.json
Linux /etc/claude-code/managed-settings.d/90-rubrik.json
Windows C:\Program Files\ClaudeCode\managed-settings.d\90-rubrik.json

Additional requirements for MDM deployments

MDM enrollment and Artifactory access are in the device requirements table. Jamf Pro supports macOS only, Microsoft Intune supports macOS and Windows, and Linux devices use manual installation.

The following table lists the operating systems that each supported MDM solution can deploy to.
MDM solution macOS Windows Linux
Jamf Pro Yes No No
Microsoft Intune Yes Yes No

Jamf Pro policy script parameters: The Jamf Pro policy script downloads the binary from Rubrik Artifactory and runs it on each device. The Jamf policy must provide the following positional parameters:

Parameter Source Description
$1 Reserved by Jamf Mount point. Not used by the script.
$2 Reserved by Jamf Computer name. Used as the device hostname.
$3 Reserved by Jamf Username. Used as the device username.
$4 User-defined Endpoint URL for agent detection.
$5 User-defined API key. Passed to the binary through the API_KEY environment variable.
$6 User-defined Artifactory URL that hosts the endpoint detection binary.
$7 User-defined Whether to install the Claude Code and Claude Cowork hooks. Accepted truthy values are:
  • true
  • True
  • TRUE
  • 1
  • yes
  • YES
  • Yes

Any other value or omission skips installing the Claude Code managed-settings hook from the Jamf Pro policy.
$8 User-defined Whether to install the Codex hooks (early access). Accepts the same values as $7.
$9 User-defined Whether to install the GitHub Copilot CLI hook. Accepts the same values as $7.
$10 User-defined Whether to install the GitHub Copilot VS Code hook. Accepts the same values as $7. The parameters are positional, so to enable a later hook alone, pass the earlier ones as empty strings. When any hook is enabled, the script copies the binary to a persistent, root-owned location so that the hooks can run it.

Additional requirements for manual installation

The scheduler and Claude Code requirements are in the device requirements table.

  • For a fleet of Linux devices, use an existing configuration management tool, such as Ansible or Chef, to run the manual installation steps.
