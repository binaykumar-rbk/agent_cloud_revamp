      Agent Cloud with RSC provides a comprehensive solution for discovering AI agents in your environment, understanding which tools they have access to, detecting risky actions they perform on your data and configurations, and rewinding unauthorized changes without downtime.

      • Introduction to Agent Cloud
      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Choose your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Choose where it runs before you connect your AI providers and agents.

      • Connect your AI agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

        • Agent Cloud support matrix

          Find out what each Agent Cloud connection discovers, captures, and can block.

        • Enterprise AI platforms
          • Microsoft Copilot Studio deployed in Agent Cloud

            Agent Cloud reads Microsoft Copilot Studio agents and conversation transcripts through the Dataverse API and, when you enable tool blocking, intercepts tool calls in real time through Copilot Studio's external threat detection integration.

          • Microsoft 365 Copilot deployed in Agent Cloud

            Agent Cloud reads Microsoft 365 Copilot interactions through the Microsoft Graph API to discover the users and agents that use Copilot and to record their sessions.

          • Microsoft Foundry (new) deployed in Agent Cloud

            Agent Cloud reads Microsoft Foundry (new) agent activity from the Azure Application Insights resource linked to a Foundry project, through a service principal that you grant read access.

          • Microsoft Foundry (classic) deployed in Agent Cloud

            Agent Cloud reads Microsoft Foundry (classic) agent activity from the Azure Application Insights resource linked to a Foundry project, through a service principal that you grant read access. Only instrumented agents are observed.

          • ChatGPT Enterprise deployed in Agent Cloud

            Agent Cloud polls OpenAI's Compliance API every 10 minutes to discover custom GPTs and ingest conversations and tool calls from a ChatGPT Enterprise workspace.

          • Claude Enterprise deployed in Agent Cloud

            Agent Cloud reads Claude Enterprise activity after the fact through Anthropic's Compliance API, using a read-only Compliance API key.

          • Google Cloud Gemini Enterprise in Agent Cloud

            Agent Cloud uses a Google Cloud service account that you create to discover agents and read their conversation sessions in a Google Cloud project, covering both Gemini Enterprise and Gemini Enterprise Agent Platform (Vertex AI Agent Engine).

            • Google Cloud Gemini Enterprise requirements for Agent Cloud

              Connecting Google Cloud Gemini Enterprise to Agent Cloud requires specific Google Cloud and RSC administrative accounts, plus Google Cloud Identity and Access Management (IAM) settings.

            • Determining Domain Restricted Sharing policy enforcement

              Determine whether your organization enforces a Domain Restricted Sharing policy, and add an exception for the Rubrik service account or the Rubrik organization domain before connecting Google Cloud Gemini Enterprise to Agent Cloud.

            • Connecting Google Cloud Gemini Enterprise to Agent Cloud

              Connect your Google Cloud Gemini Enterprise environment to Agent Cloud to discover, monitor, and enforce policies on your AI agents.

          • AWS Bedrock Agents deployed in Agent Cloud

            Agent Cloud reads Amazon Bedrock model invocation logs from Amazon CloudWatch Logs or an Amazon S3 bucket, through an IAM role in your AWS account that Agent Cloud assumes.

          • Amazon Bedrock AgentCore deployed in Agent Cloud

            Agent Cloud reads the OpenTelemetry runtime logs that Amazon Bedrock AgentCore writes to Amazon CloudWatch, through an IAM role in your AWS account that Agent Cloud assumes.

        • Custom agents

          Custom agents that you build connect to Agent Cloud through the Rubrik AI gateway, through your existing LiteLLM proxy, or by exporting OpenTelemetry traces.

        • Endpoint detection

          The Rubrik endpoint detection binary runs on employee devices to discover the AI agents installed there and the identities that use them, and, for supported agents, to capture their sessions and enforce policies in real time.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Manage Agent Cloud policies

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind AI agent changes with Agent Cloud

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

      • Administer Agent Cloud

        Control who can see and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

Connecting Google Cloud Gemini Enterprise to Agent Cloud

Connect your Google Cloud Gemini Enterprise environment to Agent Cloud to discover, monitor, and enforce policies on your AI agents.

Before you begin

Verify the following:
  • You have reviewed the steps in Determining Domain Restricted Sharing policy enforcement.
  • You have an active RSC account with the Agent Cloud entitlement.
  • You have enabled Google Cloud Gemini Enterprise for your Agent Cloud account.
  • At least one Vertex AI Agent Engine is deployed in a supported GCP region.
  • You have IAM Admin permissions in the GCP project where your agents run.

Procedure

  1. Log in to the Google Cloud CLI.
  2. Run the following command in the Google Cloud CLI to create a dedicated service account in your GCP project. 
    gcloud iam service-accounts create rubrik-agent-cloud \
  --display-name="Rubrik Agent Cloud" \
  --project=PROJECT_ID

    Here PROJECT_ID is your GCP project ID.

  3. Create and download a service account JSON key file. 
    gcloud iam service-accounts keys create rubrik-agent-cloud-key.json \
  --iam-account=rubrik-agent-cloud@PROJECT_ID.iam.gserviceaccount.com \
  --project=PROJECT_ID
    Here PROJECT_ID is your GCP project ID.
    Note:
    Keep the JSON key file secure. You will upload it to Agent Cloud in a later step.
  4. Grant the service account the minimum permissions required to discover and monitor your Vertex AI agents.
    The following table describes the minimum permissions required to discover and monitor your Vertex AI agents.
    Role Purpose Key permissions
    Vertex AI Viewer (roles/aiplatform.viewer) Discover Vertex AI Agent Engines and reads their conversation sessions and events.
    • aiplatform.reasoningEngines.list
    • aiplatform.reasoningEngines.get
    • aiplatform.sessions.get
    • aiplatform.sessions.list
    • aiplatform.sessionEvents.list
    Discovery Engine Viewer (roles/discoveryengine.viewer) Discover agents registered in Gemini Enterprise.
    • discoveryengine.engines.list
    • discoveryengine.engines.get
    • discoveryengine.agents.list
    • discoveryengine.agents.get
  5. Run these commands to bind roles to the service account. 
    gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:rubrik-agent-cloud@PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/aiplatform.viewer"

gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:rubrik-agent-cloud@PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/discoveryengine.viewer"

    Here PROJECT_ID is your GCP project ID.

    The roles/aiplatform.viewer role is required for agent discovery and session access. The roles/discoveryengine.viewer role is optional; if omitted, Vertex AI agents are discovered but are not tagged as Gemini Enterprise agents.

    Note:
    If your project uses VPC Service Controls, you must add an ingress rule permitting the service account or add the service account project to your access level. See the GCP documentation for guidance on VPC Service Controls configuration.
  6. Log in to RSC.
  7. Click and select Agent Cloud.
    The Agent Cloud page appears.
  8. Select Connectors.
  9. Click Add Connection and select Gemini Enterprise (GCP).
    Agent Cloud starts the Connect Google Cloud Gemini Enterprise wizard.
  10. Enter the connection details and click Next.
    OptionDescription
    Name A descriptive name for this connection.
    GCP Project ID The ID of the GCP project where your AI agents are deployed.
    The wizard moves to the Authorize Access page.
  11. Upload the service account JSON key file you created earlier.
  12. Click Connect.

Results

Agent Cloud creates the connection and begins discovering your Vertex AI Agent Engine and Gemini Enterprise agents across all available regions. Agents typically appear in the inventory within a few minutes.

If you have already onboarded your Vertex AI agents and granted the roles/discoveryengine.viewer role, Agent Cloud automatically discovers your Gemini Enterprise agents. You do not need to create a separate connection.
