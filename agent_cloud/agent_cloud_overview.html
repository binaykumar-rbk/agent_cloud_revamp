      • Get started with Agent Cloud

        To start using Agent Cloud, confirm the prerequisites, deploy a data plane, connect your agents, verify the setup, and then add policies.

      • Deploy your data plane

        The Agent Cloud data plane runs as a SaaS deployment that Rubrik operates, or in your own AWS VPC or Azure VNet. Decide where it runs before you connect your AI providers and agents.

      • Connect your agents

        A connection links Agent Cloud to a source of agent activity, such as an enterprise AI platform, a gateway that your custom agents use, or the endpoint detection binary on employee devices.

      • Discover and observe

        Agent Cloud builds an inventory of the agents, tools, identities, models, and MCP servers in your environment, and records what each agent does, session by session.

      • Govern and control

        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

      • Rewind agent actions

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. You can start a rewind from the Sessions page, or from any page that displays the action or alert detail tray. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

        Control who can view and manage Agent Cloud, review platform and user activity, understand who is responsible for each part of a deployment, and follow best practices for rollout and for building agents that are easier to govern.

Agent Cloud

Agent Cloud with RSC gives you visibility into AI agents and their tools, controls over their actions, and the ability to rewind their mistakes. It enforces policies in real time, detects risky actions on your data and configurations, and reverts unauthorized changes without affecting other work.

Agent Cloud blocks risky actions by autonomous AI agents as they happen, helps you find their root causes, and rewinds the actions that get through to repair your data and configurations.

The challenges of agentic AI

Organizations adopting agentic AI, meaning autonomous agents that can execute tasks, face two kinds of risk. Agents can be manipulated into doing harm, and they can make mistakes on their own. Many organizations lack visibility into what their AI agents do and which data they touch, and they have no way to stop a risky action as it happens or to undo it afterward. Static rules cannot close that gap because agents decide what to do at runtime. A rule that blocks one action can miss the same intent carried out another way.

The following scenarios illustrate these risks:

  • A developer installs a third-party skill for a coding agent such as Claude Code. Anyone can publish a skill, and installing it takes a single command. The skill hides a prompt injection that tells the agent to send credentials to an external server. The agent acts with the developer's permissions, so existing tools see nothing unusual, and a rule for specific commands or destinations misses it. Stopping it requires real-time enforcement that understands agent intent.
  • A nightly cleanup agent designed to optimize SharePoint storage deletes recent files by mistake. Days later, a user reports missing files and opens a help desk ticket. The IT team confirms the data loss but not its extent or its cause, and has no clear recovery path. Restoring from a point-in-time backup would also erase every legitimate change made since the restore point.
  • A support agent changes the type of a field and breaks a Salesforce object. Without a record of the session, the prompt, and the tool call that made the change, the team cannot tell what happened or how to restore the object.

Even with strong controls, some mistakes will get through. Organizations need both: real-time policies that block risky actions before they run, and a precise way to trace and undo the actions that slip past.

How Agent Cloud solves these problems

Agent Cloud provides a central control plane for monitoring and governing AI agents across providers and frameworks. It addresses four needs: visibility, controls, root cause analysis, and rewind.

The following table describes how Agent Cloud addresses visibility, controls, root cause analysis, and rewind.
Capability Description
Visibility Agent Cloud inventories the agents running on endpoints, in browsers, in coding tools, and across cloud and SaaS platforms, along with the tools and MCP servers they use. It monitors their activity so you can see which agents are most active, which tools they use, and whether any interaction violates your security policies.
Controls You define policies that Agent Cloud enforces at runtime. Access controls decide which apps and tool calls an agent can use. Semantic AI Governance Engine (SAGE) evaluates prompts, responses, and tool calls against policies you write in natural language, such as never edit revenue fields. Because SAGE understands meaning and intent, it can catch risks that fixed rules miss, including prompt injection.
Root cause analysis Agent Cloud records every action an agent takes, so you can trace an error, such as the SharePoint deletion, back to the specific agent, prompt, and tool that caused it.
Rewind Agent Cloud reverts the exact changes an agent made and leaves all other work intact. You can review the scope of a rewind before it runs, and a person approves it.
