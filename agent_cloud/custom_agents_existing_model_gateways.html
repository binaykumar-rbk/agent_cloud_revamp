LiteLLM

If your custom agents already route their model traffic through a LiteLLM proxy, the Rubrik plugin sends that traffic to Agent Cloud for recording and real-time policy enforcement. Review the capabilities, requirements, limitations, and responsibilities before you connect the proxy.

Your LiteLLM proxy continues to broker traffic between your agents and the model providers. The plugin sends request and response data from the proxy to Agent Cloud, and enforces block policies on that traffic. All communication is outbound from the plugin: Agent Cloud never connects to your proxy, so the proxy can run in a private network or in any environment that can make outbound HTTPS calls.

Capabilities

This table lists what the LiteLLM connection supports.
Capability Support
Model providers Any model that your LiteLLM proxy routes
Discovery Agents, tools, sessions, identities. Tools are inferred from the context that agents send to the model.
Session activity User prompts, agent responses, tool calls
Configuration violations Yes
Monitor Yes
Block User prompts, tool calls, tool responses, agent responses
Ask Not supported

For all connections, see Agent Cloud support matrix.

Requirements

  • LiteLLM version 1.74.9-stable or later for OpenAI models, and version 1.77.0 or later for Anthropic models.
  • Administrative access to the environment where your LiteLLM proxy runs.
  • Outbound HTTPS access from the proxy to the Agent Cloud webhook URL on port 443. No inbound connectivity from Agent Cloud to the proxy is required.
  • An RSC role with Data Source Management privileges.
  • A webhook URL and an API key, which you generate when you connect the proxy. The plugin uses them to authenticate its calls to Agent Cloud.

Both RSC and customer-VPC deployments of your proxy are supported.

Limitations

Blocking through LiteLLM has known limitations, including how the plugin behaves if it cannot reach Agent Cloud. Blocking fails open: if Agent Cloud cannot be reached or does not respond in time, the action proceeds. For details, see Blocking limitations and fail-open behavior.

Responsibility boundary

The following table summarizes which components Rubrik operates and which components you operate when custom agents use an existing model gateway.

This table describes the responsibility boundary between Rubrik and the customer when custom agents use an existing model gateway.
Operated by Components
Rubrik The Agent Cloud control plane, the webhook ingestion endpoint, the log processor, the Rubrik-managed object storage for session logs, and the secrets store for webhook API keys.
You The existing model gateway and the infrastructure on which it runs, the Agent Cloud plugin or webhook integration installed in the gateway, your custom agents, your accounts with the LLM providers, the upstream API keys configured in the gateway, and the outbound network path from the gateway to the Agent Cloud webhook URL.
