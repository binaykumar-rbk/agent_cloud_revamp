        • How policies work

          A policy is a named rule with a severity that Agent Cloud evaluates against your agents, tools, and sessions. When agent activity breaks a policy, Agent Cloud records a violation or an alert and, depending on the policy's enforcement mode, can stop the action.

        • Enforcement modes

          A policy's enforcement mode determines what happens when agent activity breaks it: Monitor records an alert, Block stops the action before it runs, and Ask hands the action to the agent's own approval prompt.

        • How blocking works

          A Block policy lets Agent Cloud stop an agent action before it takes effect, inline with the agent's own execution, instead of only flagging it afterward.

        • Agent Cloud system policies

          Agent Cloud includes multiple system policies. These policies are not enabled by default. You can enable them from the Policies page.

        • Agent Cloud policy packs

          Agent Cloud policy packs are curated collections of system policies you can add to your Agent Cloud account to enable a focused set of controls for a specific risk area, compliance framework, or industry.

        • Custom policies

          A custom policy is a rule that you write in plain English. The Semantic AI Governance Engine (SAGE) turns it into a policy that it judges against agent activity by intent, not by matching keywords.

        • Alerts and violations

          Alerts and violations are the findings that your policies produce. An alert is a specific action or message that broke a policy. A violation is a standing configuration that breaks one.

        • Viewing insights

          View the Insights page to review security recommendations and posture improvements identified by Agent Cloud.

        • MCP access policies (Early access)

          An MCP access policy decides which identities can use an MCP server, or a specific tool on it, through your MCP gateway.

      • Rewind agent actions

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. You can start a rewind from the Sessions page, or from any page that displays the action or alert detail tray. Rewind requires a complete Rubrik snapshot taken within seven days before the action.

How policies work

A policy is a named rule with a severity that Agent Cloud evaluates against your agents, tools, and sessions. When agent activity breaks a policy, Agent Cloud records a violation or an alert and, depending on the policy's enforcement mode, can stop the action.

The policy model

This table describes the elements of a policy.
Element Description
Effect A policy allows or denies behavior. Enforcement is deny-oriented: deny rules stop or flag actions, an allow rule never causes a block, and a deny always takes precedence over an allow.
Rule A policy is either structured, naming specific tools, agents, or models, or written in natural language and judged by SAGE. For more information, see Custom policies.
Scope A policy can apply to all agents and tools, or be scoped to specific ones.
Severity Critical, High, Medium, or Low. Agent Cloud uses severity to prioritize the alerts and violations that the policy produces.
Source System policies are provided by Rubrik and cannot be deleted. You can enable, disable, and configure them, and add them in groups with policy packs. Custom policies are ones that you write.
Enforcement mode Monitor, Block, or Ask. For more information, see Enforcement modes.

Violations and alerts

Every policy produces findings when it is broken, whatever its enforcement mode:

  • A violation is a standing configuration that breaks a policy, such as a tool that an agent has access to, or the model that a session runs on.
  • An alert is a specific action or message in a session that breaks a policy, such as a tool call or a prompt.

Violations appear under Posture > Violations, and alerts under Runtime > Alerts. For more information, see Alerts and violations.

Policy exceptions

An exception excludes a specific tool or agent from a policy, so that its activity no longer produces alerts, violations, or blocks under that policy. You can add an exception in either of two ways:

  • From a tool: click Inventory > Tools, select the tool, click the More icon, select Create Policy Exception, and choose the policies. For more information, see Tools.
  • From an alert or violation, by marking it as safe. For more information, see Marking alerts and violations as safe.

Viewing the Agent Cloud policies

View the list of policies that govern Agent Cloud.

About this task

The Policies page lists each policy with its status, severity, enforcement mode, active violations and alerts, number of exceptions, and source. You can filter the list by status, enforcement, or source.

The Exceptions tab lists the tools and agents that are excluded from a policy. It appears only for policies that support exceptions. For what an exception does, see Policy exceptions.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Click Policies.
    Agent Cloud displays the Policies page. The My Policies tab is selected by default and lists the policies that govern Agent Cloud.
  4. Optional: Click the policy name to open the policy details page.
    The policy details page includes these tabs.
    TabDescription
    Overview Displays the policy definition, including the goal, instructions, key definitions, and reference examples for safe and violating content, and a policy summary.
    Scope Displays the AI agents and tools to which the policy applies.
    Exceptions Displays the AI agents or tools that are exempted from the policy. Agent Cloud displays the Exceptions tab only when the policy supports exceptions.
    Violation Displays a list of violations that occurred due to this policy.
    Alerts Displays a list of alerts that resulted from this policy.

Results

The Policies page displays the active policies for Agent Cloud.

Enabling or disabling Agent Cloud policies

Enable or disable policies to control which agent actions Agent Cloud monitors and enforces.

About this task

Disabling a policy stops it from producing findings for all agents and tools. To exclude only one tool or agent, add an exception instead. For more information, see Policy exceptions.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Click Policies.
    Agent Cloud displays the Policies page, which contains a list of the policies that govern Agent Cloud.
  4. Click My Policies.
  5. Click and select Enable Policy or Disable Policy.
    You can also enable or disable policies from the Policy Packs page and the policy details page.
  6. Click Enable or Disable.

Results

The selected policies are enabled or disabled. Agent Cloud applies the updated governance rules immediately.
